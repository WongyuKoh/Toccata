# 규칙
- 사양이 **같거나 설계상 동등**해야 한다(치수·재질·핀 배치·용량). 애매하면 "동등 여부"에 이유를 쓰고 verified=false.
- 가격·재고·배송비는 **실제 상품 페이지를 열어** 확인한다(WebFetch, 안 되면 WebSearch 결과 스니펫; 그래도 안 되면 추정이라고 표시). 오늘 2026-09-30.
- 필요한 수량(qty_needed)과 판매 단위(팩)를 반영해 **필요 수량을 사는 데 드는 총액**을 계산한다.
- 각 품목마다 후보를 최대 3개(허브 판매처 우선). 후보가 없으면 "없음"과 찾아본 곳을 쓴다.
- 결과는 지정 JSON 파일에 쓴다. 채팅에 긴 설명 금지, 마지막 답은 5줄 요약.

# 출력 JSON 형식 (list)
[{"id":"i082","current":{"store":..,"total":..},"candidates":[{"store":"엘레파츠","seller":"..","url":"..","product":"상품명 그대로","pack_qty":..,"pack_price":..,"buy_packs":..,"total":..,"spec_match":"같음/동등/다름 + 이유","stock":"재고 있음/품절/미확인","verified":true,"note":".."}]}]
또, 조사하다 알게 된 판매처 배송비 규정은 "_ships" 키 대신 별도 파일 없이 목록 마지막 원소로 {"id":"_ships","ships":[{"store":..,"fee":..,"free_over_vat_incl":..,"url":..}]} 를 넣는다.
