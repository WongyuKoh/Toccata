## 1. 요구사항 (R)

### 1.1 음원 — 소리를 만드는 프로그램

| ID | 요구 | 원문 요지 |
|---|---|---|
| R1 | 피아노 소리를 낸다 | "피아노 소리를 낼 수 있는 것" |
| R2 | 누르는 세기·속도에 따라 소리가 달라진다 | "누르는 파워, 스피드에 따라 소리의 크기가 달라지잖아" |
| R3 | 댐퍼 페달을 지원한다 | "댐퍼 페달도 있으니까 그것도 되는 프로그램" |
| R4 | 88키 전부, 시간 제한 없이 동작한다 | "키 제한과 시간 제한 없는 프로그램" |
| R5 | 무료이거나 비용이 적게 들고, 위 기능을 모두 제공한다 | "무료거나 비용이 얼마 안 들면 좋을 거 같고, 내가 말한 기능을 모두 제공해야" |
| R6 | 실제 피아노처럼 동작한다 | "실제 피아노처럼 작동되게 할 수 있는 프로그램 혹은 오픈소스" |

### 1.2 입력 — 건반·페달에서 신호로

| ID | 요구 | 원문 요지 |
|---|---|---|
| R7 | 건반을 얼마나, 어느 속도로 눌렀는지와 페달 여부를 전달한다 | "건반이 어느정도, 어느 속도로 눌렸는지를 측정해서 정보를 전달… 페달 여부도" |
| R8 | 입력 신호는 우리가 변환해서 제공한다 | "입력 신호를 변환을 해서 제공을 할 수밖에 없어" |
| R9 | 하드웨어는 그대로 두고 음원 소프트웨어만 바꿀 수 있다 | "하드웨어는 동일하고 소프트웨어만 바꾼다고 하면 호환이 될까?" |

### 1.3 구현 방식

| ID | 요구 | 원문 요지 |
|---|---|---|
| R10 | 음원 칩이 아니라 소프트웨어로 소리를 만든다 | "그러면 소프트웨어로 해보자" |
| R11 | 꼭 라즈베리파이일 필요는 없다 | "라즈베리파이가 아니여도 되는데" |

### 1.4 소리 출력 — 앰프와 스피커

| ID | 요구 | 원문 요지 |
|---|---|---|
| R12 | 프로그램 + 앰프 + 스피커가 모두 호환되고 음질 그대로 동작한다 | "3개가 모두 호환 및 음질 그대로 작동이 되는 구성" |
| R13 | 스피커는 피아노 본체에 부착한다. 완제품보다 부품형 | "우리 피아노에 부착형… 아두이노 스피커에 가까운 제품" |
| R14 | 좋은 스피커와 앰프로 음량 손실이 없어야 한다 | "좋은 스피커를 사용해서 음량손실이 없게" |
| R15 | 헤드폰을 꽂으면 스피커가 꺼진다 | "2번방식으로 가는데" (② = 헤드폰 자동 차단 구성) |
| R16 | 88키 모두 소리가 깨지지 않고 제대로 나온다 | "88키 모두 소리가 깨지는 거 없이 제대로 나오게" |

### 1.5 기준선 — "실제 피아노처럼"의 의미

R2·R3는 고급 기능이 아니라 **지금 팔리는 입문형 디지털 피아노도 갖춘 기본기**다(Yamaha P-145, Roland FP-10에서 확인).

| 항목 | 입문형 디지털 피아노 | Toccata 목표 |
|---|---|---|
| 세기 → 음량·음색 | 있음 | 있음 |
| 페달 공명 | 있음 | 있음 |
| 하프페달 | 본체는 지원, 동봉 스위치 페달로는 불가(연속형 페달 별매) | 있음 |
| 스피커 | P-145: 7W×2, 12×8cm 타원 ×2 | 이 이상의 음량 |
| 최저음 | 실제 그랜드도 A0(27.5Hz) 기본음은 가장 강한 배음보다 최대 25dB 약하다 | 27.5Hz를 크게 내는 것이 아니라 **찌그러짐 0**. ~~30~100Hz 채움~~ → R25로 서브를 두지 않는다(P-145처럼 최저 옥타브는 배음으로 들린다) |

### 1.7 진행 방식

- 후보는 최대한 많이 찾고 보고서로 정리한다
- 부품은 이미지, 세부 스펙, 구매처 링크, 가격을 함께 보여 주어 바로 확인할 수 있게 한다
- 건반 구조는 도형 추상화가 아니라 **실제 치수를 기입한 평면도·측면도**로 설계한다. 그 도면대로 CAD를 짜면 실제로 구현되는 수준이어야 한다
- 기존 설계 자료는 참고하지 않고 이 문서만 기준으로 새로 설계한다
- 참고 영상은 §3의 분석을 기준으로 삼는다

## 2. 도출 조건 (D)

요구사항을 지키는 데 필요한 기술 조건이다. 사용자가 직접 말한 것이 아니라 조사에서 나왔다.

### 2.1 펌웨어 (Pico)

| ID | 조건 | 이유 |
|---|---|---|
| D1 | 페달 CC64를 0/127 대신 ADC 연속값으로 보낸다. 발을 뗐을 때는 정확히 0, ±2 이상 변할 때만 송신 | R3 하프페달. 켜짐/꺼짐 엔진에서 64 경계 떨림 방지 |
| D2 | Note Off는 정식 `0x80`, 릴리즈 벨로시티 하한 5 | Pianoteq에서 1이면 댐퍼가 내려가지 않는다는 보고 |
| D3 | 모듈마다 USB 제품 이름을 다르게 준다 (`Toccata O1`~`O7`, `Toccata PED`) | 고장 난 모듈 특정, 연결 스크립트 단순화 |
| D4 | 하드웨어 편차 보정(건반별, 흑건/백건)은 펌웨어에, 취향 곡선은 엔진에 둔다 | R9. 엔진을 바꿔도 펌웨어를 다시 보정할 필요가 없다 |
| D5 | ~~CC66(소스테누토)·CC67(소프트)도 보낸다~~ → R24로 페달을 두지 않는다(펌웨어 처리 코드는 남겨도 무해). 선택: CC88 고해상도 벨로시티 | 이해하는 엔진만 쓰고 나머지는 무시한다. 오동작은 없다 |

### 2.2 Pi 5와 소프트웨어

| ID | 조건 | 이유 |
|---|---|---|

### 2.4 검증 — 소리 게이트

R16의 합격 기준.

1. 최악 조건 연주 파일을 만든다: 88키 반음계 ff + 페달, A0~C2 뭉친 화음 최대 세기 + 페달, 옥타브 글리산도, A0 연타
2. 디지털 피크가 −3dBFS 이하인지 확인한다
3. 20~300Hz 사인 스윕을 최대 볼륨으로 튼다: 덜그럭거림·바람 소리가 없어야 하고, 건반 센서의 유휴 흔들림도 기준 안이어야 한다
4. 최악 조건 파일을 최대 볼륨으로 녹음한다: 모든 건반에서 찌그러짐이 없어야 한다
5. 통과한 볼륨보다 3dB 낮은 곳을 볼륨 상한으로 고정한다
