## 1. 모듈 분해 — 도~시가 반복 단위

```
 A0 A♯0 B0 │ C1…B1 │ C2…B2 │ C3…B3 │ C4…B4 │ C5…B5 │ C6…B6 │ C7…B7 │ C8
 ─ 시작 ─  │←──────── 완전히 동일한 옥타브 모듈 × 7 ────────→│ ─끝─
    3키    +                  12 × 7 = 84키                  +  1키  = 88
```

| 모듈 | 음역 | 건반 | 백건 | 폭 | 수량 |
|---|---|---|---|---|---|
| **S** 시작 | A0 – B0 | 3 | 2 | 47.0 mm | 1 |
| **OCT** 옥타브 | C – B | 12 | 7 | **164.5 mm** | **7** |
| **E** 끝 | C8 | 1 | 1 | 23.5 mm | 1 |
| | | **88** | **52** | **1222.0 mm** | 9 |

- 옥타브 내 반음 피치 = 164.5 ÷ 12 = **13.708 mm** — 이 값이 모든 기구 설계의 폭 예산입니다.
- **PCB는 2종뿐**: 옥타브용 164.5mm ×7, 엔드피스용 47mm ×2(끝 모듈은 키 1개만 실장). 회로도·BOM·펌웨어는 완전히 1종 공유.
- S/E에 옥타브 PCB를 그대로 쓰고 일부만 실장하는 안은 **기각** — 시작 모듈 왼쪽에 117.5mm 빈 판이 튀어나와 전체 폭이 1339.5mm가 되어 요구를 위반합니다.

## 2. 시스템 아키텍처

```
        ┌── 탈착식 연산 도크 (우측 치크 측면) ──┐
        │  Raspberry Pi CM5  ·  샘플 음원      │
        └──────────── I2S ─────┬───────────────┘
                               │
 ┌───────────────────── 본체 (도크 없이도 완전 동작) ─────────────────────┐
 │  좌 치크: 스파인 RP2350 — 버스 마스터 · USB-MIDI · 폴백 신스           │
 │           DAC ×2 · 아날로그 합산 · 앰프 · 전원부                      │
 │                                                                       │
 │  [S][OCT1][OCT2][OCT3][OCT4][OCT5][OCT6][OCT7][E]  ← 능동 모듈 9개    │
 │   ↓    ↓     ↓     ↓     ↓     ↓     ↓     ↓    ↓   각각 포고핀으로   │
 │  ══════════ 공통 베이스 레일 (6061, 버스 내장) ══════════  레일에 접속 │
 │  스피커 L                                              스피커 R       │
 └───────────────────────────────────────────────────────────────────────┘
```

**세 가지 핵심 결정**

1. **모듈은 능동(자체 MCU 보유)** — 수동으로 하면 조인트 배선이 42핀으로 폭발하고, 1.3m 버스 기생용량 300pF 때문에 전체 스캔이 480µs(2.1kHz)로 떨어져 벨로시티 요구가 붕괴합니다. 능동이면 스캔이 모듈 내부 60mm 배선에서 끝납니다.
2. **버스는 모듈끼리 물리지 않고 레일이 나른다** — 모듈은 아래로 향한 포고핀으로 레일 상면 패드에 접속합니다. 조인트마다 커넥터를 두는 방식보다 오염·공차·핫플러그가 모두 유리합니다.
3. **도크는 음질 카트리지이지 생명줄이 아니다** — 도크를 빼도 USB-MIDI, 내장 스피커, 헤드폰이 전부 살아 있습니다. 상실하는 것은 고음질 샘플 음원뿐입니다.

## 3. 건반 개별 탈착 기구 ⚠️ 재설계됨

> **초기 안(후방 트러니언 + 스냅 립)은 검증에서 성립 불가 판정을 받았습니다.**
> ① 크래들이 필요로 하는 폭 18.0mm > 반음 피치 13.708mm — 물리적으로 12개가 안 들어감
> ② 유지력을 평면 램프 공식으로 계산해 약 8배 과대평가 (주장 15N, 실제 최대 1.80N)
> ③ 매 릴리즈마다 **1.93N**이 이탈 방향으로 걸림 → 유지력 1.80N보다 커서 **세게 치면 건반이 튀어나옴**
> ④ 리턴을 돔이 담당하는 구조라 업웨이트가 9.0gf뿐 — 실리콘 히스테리시스 25%만 넣어도 **복귀 불능**

### 3.1 해결: 리턴 스프링을 피벗 뒤로

문제의 근원은 **리턴력을 피벗 앞(돔)이 만든다**는 것이었습니다. 그러면 복귀 순간 돔이 건반을 위로 밀어내고, 그 힘이 그대로 피벗을 이탈 방향으로 밀어 올립니다. 스프링을 피벗 뒤로 옮기면 부호가 뒤집힙니다.

```
        테일 판스프링(아래로 누름)
              ↓ F_tail
    ┌─────────┴──┐
    │  테일 40mm │══◎═══════════════════════════════════┐  ← 건반
    └────────────┘  ↑                    ↑              │
              피벗 X=0            돔 s=45mm        타건점 X=170
                 ▼ R (항상 아래로 눌림)
            개방형 C 시트 — 스냅 립 없음
```

| 조건 | 피벗 반력 R | 의미 |
|---|---|---|
| 정지 | **+1.82 N** | 시트를 누름 |
| 릴리즈 스냅 최악 | **+1.39 N** | 시트를 누름 |

**하중 방향이 항상 시트를 누르는 쪽이므로 스냅 립이 아예 필요 없습니다.** 13.708mm 피치에 립을 욱여넣는 문제, 유지력 계산 문제, 이탈 문제가 한 번에 소멸합니다. 어쿠스틱 피아노가 밸런스핀에 건반을 얹어두는 것과 같은 원리입니다.

### 3.2 사양

| 항목 | 값 | 비고 |
|---|---|---|
| 피벗 | SUS303 트러니언 φ3.0 h7 × **L12.0mm**, 편측 1.0mm 돌출 | 중앙 널링 압입으로 축방향 이탈 방지 |
| 시트 | POM 개방형 **C 시트(전방 +X 개구)** | 립 없음. 연주 하중(↓)과 인출 방향(→)이 직교 |
| 테일 판스프링 | 옥타브당 12핑거 빗(comb) 1개, SUS304 t0.3 | 백건 핑거 **1.68 N** / 흑건 핑거 **1.12 N** |
| 탈착 | 전단을 살짝 들어 업스톱 해제 → **앞으로 당김** | 테일이 판스프링 밑에서 빠져나옴. 공구 불필요 |
| 장착 | 뒤로 밀어 넣음 → 딸깍 | 백건 7종·흑건 2종의 형상 차이로 오삽입 물리 차단 |
| 다운웨이트 | 백건 **52 gf** / 흑건 **57 gf** (Δ5gf) | 빗 핑거 폭으로 조정. 체감 한계 ±5gf 이내 |
| 업웨이트 | **25 gf** | 초기 안 9.0gf → 복귀 불능이었음 |
| 키 질량 | 백건 31g / 흑건 18g, 88키 합 2.26 kg | |

> **흑건 무게 문제도 여기서 해결됩니다.** 흑건은 타건점이 피벗에 더 가까워(145mm vs 170mm) 같은 스프링을 쓰면 초기 안에서 82~89gf가 나왔습니다(주장 58gf). 빗 핑거를 흑건만 66%로 약화시키면 같은 부품 1개 안에서 57gf로 맞춰집니다.

### 3.2.1 ⚠️ 다운웨이트는 러버돔 반력에 종속된다 — 금형 발주를 가르는 지점

테일 스프링과 러버돔의 힘은 **더해집니다.** 그런데 돔의 반력이 어느 정도인지에 따라 결과가 완전히 달라집니다.

| 돔 종류 | 돔 rest / 피크 | 테일 스프링 | 결과 UW | 결과 **DW** |
|---|---|---|---|---|
| **전용 경량 돔** (센서 전용) | 0.15 / 1.15 N | 1.68 N | 25 gf | **52 gf** ✓ |
| **도너 표준 돔** (일반 디지털피아노) | 1.05 / 2.85 N | 0.67 N | 25 gf | **74 gf** ✗ |

도너 돔으로 52gf를 맞추려면 테일 스프링이 **−0.23N**, 즉 테일을 위로 당겨야 하는데 그러면 피벗 반력의 부호가 뒤집혀 §3.1의 구조가 통째로 붕괴합니다. **도너 돔으로는 52gf에 도달할 수 없습니다.**

따라서 선택지는 셋뿐입니다.

1. **다운웨이트 목표를 74gf로 상향** — 도너 돔 그대로 사용, 금형비 0원. 다만 74gf는 세미웨이티드로는 무거운 편입니다.
2. **전용 경량 돔 금형 발주** — 52gf 달성, 압축성형 금형 **₩200~350만 · 리드타임 4~6주 · MOQ 500**.
3. 도너 돔의 스커트를 가공해 반력을 낮춤 — 88키 재현성 확보가 어려워 비권장.

**이 결정이 1단계 예산의 최대 단일 변수입니다.** 0단계(도너 실측)에서 실제 돔 F-S 곡선을 얻은 뒤에 결정합니다.

### 3.2.2 산포 예산 — 목표를 현실화

테일 스프링 + 돔 rest/피크 + 예압립 마찰(0~9.5gf) + 돔 로트 산포(±11.5gf) + 성형 공차가 각각 따로 계산되어 있어 통합 총합이 없었습니다. 합치면 ±15gf를 넘어 체감 한계의 3배가 됩니다.

- 목표를 **52 ± 8 gf, 인접 키 간 차 ≤ 3 gf**로 현실화합니다(±5gf는 물리적으로 불가능).
- 대책: ① 1대분 러버 스트립 **동일 로트 강제** ② 테일 빗 핑거 폭 **3등급 선별** ③ 예압립을 저강성 실리콘으로 바꿔 간섭 변동 감도를 낮춤.
- 아연 웨이트로 조정하려는 초기 안은 권한이 3.5gf뿐이라 무효입니다.

### 3.3 키에는 전기 접점을 두지 않는다

이 결정은 검증을 통과했고 유지합니다. 2접점 스위치는 전량 옥타브 PCB 위의 러버돔 + 카본 패드로 만들고, 건반은 돔을 누르는 플라스틱 플런저만 갖습니다.

- **전기 삽발 사이클 0회** — 포고핀·카드엣지·ZIF가 전부 불필요
- 88키 × 3핀 = 264 분리형 접점이라면 접점당 연간 불량률 0.1%만 가정해도 **1 − 0.999²⁶⁴ = 23.2%** 확률로 매년 최소 1개가 고장납니다
- 3.3V / 0.1mA 미만 dry circuit에서는 기계 수명보다 산화막·프레팅이 먼저 오고, 접촉저항 상승이 곧 **타이밍 오차 = 벨로시티 오차**입니다
- 러버 시트에 플런저 관통부 스커트를 성형해 **건반을 빼도 PCB는 실리콘으로 완전히 덮인 상태**를 유지 — 개별 탈착 구조의 최대 약점인 이물 침투를 원천 차단

## 4. 2접점 센싱과 벨로시티

### 4.1 접점 배치 (재조정)

초기 안은 접점2가 스트로크의 73%에 있어 오버트래블 2.7mm가 남았고, 검증에서 "좌굴 직후 건반이 0.30 m/s로 자유낙하해 **가장 여리게 치려 할 때 바닥 타격음이 가장 크게 들린다**"는 지적을 받았습니다. 발음점을 뒤로 옮깁니다.

| | 전단 변위 | 플런저 환산 |
|---|---|---|
| 접점 1 (NO1) | 5.5 mm (55%) | 1.178 mm |
| 접점 2 (NO2) | **8.6 mm (86%)** | 1.842 mm |
| 간격 | **3.1 mm** | 0.664 mm |
| 바닥 스톱 | 10.0 mm | 2.14 mm |
| 오버트래블 | **1.4 mm** | 0.30 mm ✓ |

### 4.2 벨로시티 분해능

```
dt = 접점 간격 ÷ 건반 속도
  fff (0.9 m/s)   → dt =   3.44 ms
  ppp (0.015 m/s) → dt = 207    ms
로그 매핑 127단계 → 스텝당 3.30%
dt 최소점에서 1스텝 = 114 µs
25 kHz 스캔(40 µs) = 0.35 스텝  ✓ 127단계 전부 분해
```

간격을 1.8mm에서 3.1mm로 넓힌 결과 분해능이 **오히려 좋아졌습니다**(0.61 → 0.35 스텝). 참고로 v0.1의 4kHz 스캔이었다면 3.62스텝을 건너뛰어 fff 구간이 4단계씩 계단화됩니다.

- **디바운스 금지**: 에지를 0.5~5ms 지연시키면 dt 자체가 오염됩니다. 첫 에지를 즉시 채택하고 해당 접점만 3ms 락아웃.
- **릴리즈 벨로시티 무료 획득**: 접점2 open → 접점1 open의 dt. 부품 추가 0개, 리듬게임 롱노트 판정에 사용.
- 타임아웃은 **350 ms**입니다. dt 상한이 207ms인데 초기 안의 200ms 타임아웃을 그대로 두면 **가장 여린 ppp 타건이 구조적으로 무음**이 됩니다.
- dt 범위·로그 매핑 상수·타임아웃은 전부 **펌웨어 설정값으로 빼고 하드코딩을 금지**합니다. 실측(1-A1) 전까지 전부 잠정치입니다.

### 4.3 ⚠️ 발음 기준과 판정 기준을 분리한다

노트온을 접점2 시각으로 보고하면, 같은 손가락 동작이라도 **세기에 따라 보고 시각이 최대 207ms 이동**합니다. 이건 상수 오프셋이 아니라 세기 의존이라 캘리브레이션으로 흡수되지 않고, 하드웨어에서 아낀 350µs보다 **600배 큰 항**입니다.

| 사건 | 기준 시각 | 용도 |
|---|---|---|
| 발음 (오디오) | **접점2** 닫힘 | 실제 피아노와 동일 |
| **게임 판정** | **접점1** 닫힘 = t2 − dt | 세기 의존 편차 제거 |
| 노트오프 | 접점2 열림 | |

모듈이 이미 t1을 래치하고 있으므로 이벤트에 **raw dt(16bit)**를 함께 실어 컨트롤러가 t1을 복원합니다. 또한 age 필드 단위를 4µs → **8µs**로 바꿔 범위를 2040µs로 넓힙니다(스캔 양자화가 40µs이므로 해상도 손실 0).

## 5. 옥타브 모듈 (12키) 내부

| 항목 | 사양 |
|---|---|
| 스위치 | 12키 × 2접점 = 24개 |
| 매트릭스 | **4 드라이브 × 6 센스 = 24노드** (사용률 100%) |
| 다이오드 | **BAT54W 쇼트키** ×24 — 1N4148은 접점저항 1kΩ에서 로우레벨 0.909V로 마진 붕괴 |
| 접점 패드 표면처리 | **ENIG 금지** → 시제품 하드골드(Au 0.75~1.25µm), 양산 carbon-over-copper 인쇄 |
| 센스 풀업 | 47 kΩ + **프리차지 기법** — 접점저항 5kΩ에서도 0.61V (VIL 0.99V 대비 마진 0.38V) |
| 비선택 행 | Hi-Z (쇼트키 역누설 DC 경로 제거) |
| 스캔 | 3.0 µs/행 × 4행 = 12 µs, 주기 **40 µs (25 kHz)** |
| MCU | **RP2354A** (RP2350 + 내장 2MB 플래시) + **12MHz 크리스털** |
| 소비 | 모듈당 약 40 mA @3.3V |

> **크리스털은 생략 불가**: 두 검증자가 독립적으로 지적했습니다. TDMA 슬롯 타이밍을 각 슬레이브가 로컬 클록으로 세는데, RP2350 내장 RC 오실레이터는 정밀도가 부족해 슬롯이 밀립니다. 모듈은 **12 MHz**(UART/TDMA 전용), 스파인은 **12.288 MHz**(I2S BCLK 정수 분주)로 서로 다른 크리스털을 씁니다 — 12MHz로 BCLK를 만들면 분주비가 48.83으로 정수가 아니어서 ±6.7ns 지터가 DAC SNR을 깎습니다.

> **ENIG를 쓰면 안 되는 이유**: 초기 안은 "ENIG 필수, HASL 금지"였는데 이것이 뒤집혔습니다. ENIG의 금층은 0.05~0.1µm에 불과해, 러버 카본 필이 반복 마찰하는 슬라이딩 접점에서는 **수천~수만 타건 만에 뚫리고 노출된 니켈이 산화**합니다. 접촉저항이 수십 kΩ으로 오르면 47kΩ 풀업의 트립 임계(약 16kΩ)를 넘고, 증상은 "건반이 가끔 안 눌린다"가 됩니다. 시제품은 접점 영역 하드골드 선택 도금, 양산은 카본 인쇄로 갑니다. 발주 전 벤더 3곳에 카본 인쇄 지원 여부·MOQ와 하드골드 단가를 견적받아야 합니다.

**시작/끝 모듈**은 47mm PCB 1종을 공유합니다. 시작은 키 3개, 끝은 키 1개만 실장하고, 끝 모듈의 남는 23.5mm는 우측 치크블록으로 흡수합니다.

## 6. 공통 베이스 레일과 공차 — 이 설계의 최대 위험

### 6.1 왜 모듈을 서로 물리면 안 되는가

| 방식 | 최악 누적 | RSS |
|---|---|---|
| 모듈끼리 체결 (chain) | ±1.20 mm | ±0.316 mm |
| **공통 레일 절대 위치결정** | **±0.070 mm** | **±0.044 mm** |

체인 방식은 조인트 8개의 오차가 누적됩니다. 레일에 각 모듈을 개별 위치결정하면 9번째 모듈도 2번째 모듈과 오차가 같습니다 — **누적이 발생하지 않습니다**.

기준점: 개별 건반의 부싱 좌우 유격이 ±0.05mm입니다. 레일 방식(±0.044mm)은 **이미 건반 자체의 노이즈 플로어 아래**에 도달했고, 체인 방식은 그보다 6~24배 큽니다.

### 6.2 경계 벽 두께는 0 mm여야 한다

가장 반직관적이지만 가장 중요한 기구 결정입니다.

| 경계 벽 (각 측) | 건반 사이 갭 | 판정 |
|---|---|---|
| 0 mm | 1.20 mm (모듈 내부와 동일) | ✓ |
| 0.5 mm | 1.40 mm (+17%) | 경계선이 보이기 시작 |
| 1.2 mm (사출 최소) | 2.80 mm (+133%) | 즉시 식별 |

따라서 **모듈 섀시는 건반 하면보다 4mm 아래에서 끝나는 U-채널**로 만들고 양단 건반을 섀시 바깥으로 오버행시킵니다. 갭 아래에는 흑색 펠트를 깔아 내부 갭과 같은 시각 인상을 만듭니다.

## 7. 모듈 버스와 자동 주소 할당

**동일한 옥타브 모듈 7개가 자기 위치를 아는 방법**이 핵심 문제입니다.

| 항목 | 사양 |
|---|---|
| 물리계층 | RS-485 반이중, **4 Mbps** (2 Mbps 폴백) |
| 트랜시버 | SN65HVD75 — v0.1의 THVD1450은 500kbps 상한이라 **사용 불가** |
| 방식 | 마스터 POLL 브로드캐스트 기반 고정 슬롯 **TDMA** |
| 주소 결정 | **레일 스테이션 하드와이어 ID** (3비트 코드 또는 E96 저항 1개, 스테이션당 약 100원) |
| 이벤트 | 3바이트 `[on/off + key][velocity][age]` |
| 열거 시간 | 약 6 ms |

**왜 데이지체인 열거가 아니라 스테이션 ID인가**: 초기 안은 CHAIN 데이지체인 자동 열거였지만, 공통 레일을 채택한 순간 중복 기능이 됩니다. 레일에 스테이션 9곳이 이미 물리적으로 고정되어 있으므로 레일이 직접 ID를 주면 됩니다. 더 중요한 것은 데이지체인의 실패 모드입니다 — 중간 모듈 하나가 열거에 실패하면 **하류 전체가 1옥타브 낮게 매핑되어 "조용히 틀린 음정으로 소리남"**이 됩니다. 스테이션 ID는 순서가 아니라 **위치**가 음정을 정하므로, 모듈 하나가 죽어도 나머지는 올바른 음정으로 울리고 "몇 번 스테이션이 비었다"를 정확히 표시할 수 있습니다. DIP 스위치는 사용자가 매번 맞춰야 하고 중복 설정 시 버스 충돌로 두 모듈이 함께 죽으므로 기각합니다.

**노트 매핑은 단일 식이 아니라 베이스 테이블로**:

```
base[] = { 12, 24, 36, 48, 60, 72, 84, 96, 108 }    # 스테이션 0~8
note = base[station] + key_index
```

`note = 12 + 12×addr + key_index` 단일 식은 성립하지 않습니다. 끝 모듈(C8)은 시작 모듈과 47mm 엔드피스 PCB를 공유하는데, 시작 모듈이 슬롯 9·10·11을 쓰므로 끝 모듈도 물리적으로는 슬롯 9에 앉습니다. 그대로 대입하면 `12 + 96 + 9 = 117 (F8)`이 나옵니다. 모듈 타입별 매핑이 필요합니다.

### age 필드 — 리듬게임 판정의 핵심

각 이벤트에 **발생 시각과 송신 시각의 차이(4µs 단위)**를 실어 보냅니다. 버스 대기시간이 타임스탬프를 오염시키지 않으므로, 게임이 실제로 보는 지터는 **스캔 양자화 ±20µs뿐**입니다. 60fps 프레임(16.7ms) 대비 800배 여유입니다.

**핫플러그**: 기능으로 지원하지 않되 파손 없이 생존하고 자동 재열거로 복구하는 등급으로 정의합니다. 핀 길이 스태거(GND 최장 → 프리차지 → 메인 5V → 신호 최단) + 모듈별 소프트스타트로 파손을 막고, 이탈 감지 시 **All Notes Off**로 스턱 노트를 방지합니다.

## 8. 탈착식 연산 도크

**"실시간은 본체에, 연산은 도크에."** 도크에는 느리게 부팅하고, 뜨겁고, 나중에 교체될 것만 넣습니다.

| | 본체 (**좌 치크**) | 도크 (**좌 치크 바깥 벽**) |
|---|---|---|
| 담당 | 버스 마스터 · 타임스탬프 · USB-MIDI · 폴백 신스 | 고음질 샘플 음원 · 설정 UI |
| 부품 | RP2350 스파인, DAC ×2, 앰프, 스피커, 헤드폰, 전원부 | Raspberry Pi CM5 (4GB / 32GB eMMC) |
| 부팅 | **0.4 초** | 12~18 초 |

- **도크를 빼도 피아노는 소리가 나고 USB-MIDI도 나갑니다.** 상실하는 것은 샘플 음원뿐입니다.
- 전원 인가 즉시 스파인 폴백 신스가 소리를 내고, 파이가 준비되면 조용히 넘어갑니다 — **대기 화면이 존재하지 않습니다.**
- **키 스캔을 리눅스에 맡기지 않는 이유**: dt 최소 3.4ms 구간에서 1% 분해능을 얻으려면 20µs 정확도가 필요한데, 표준 커널의 GPIO 인터럽트 지터는 50µs~수 ms, PREEMPT_RT도 최악 100µs급입니다. RP2350은 ±1µs를 보장합니다.
- **SD카드 손상 우려는 매체를 바꿔 제거합니다** — CM5의 eMMC + overlayfs read-only 루트. UPS로 완화할 문제가 아닙니다.
- **팬 금지** — 25dBA 팬 소음은 pp 연주 구간을 파괴합니다. 알루미늄 압출 셸을 히트싱크로 쓰고 지속 소비를 6.5W로 상한 고정.

**도킹 커넥터**: 초기 안의 PCIe x1 엣지 슬롯은 삽발 수명 주장(10,000회)이 검증에서 반박되었습니다(PCI-SIG 실제 규격은 50~250회 수준). 하드골드 처리 카드에지 또는 Samtec MEC8급으로 재검토가 필요하며, 이는 **미확정 항목**입니다.

> **도크와 스파인은 같은 쪽(좌측 = 저음부) 치크에 둡니다.** 초기 안은 스파인 좌측 / 도크 우측이었는데, 그러면 도크↔스파인 UART와 I2S가 **1.25m를 가로질러야** 합니다. 도크의 I2S 디지털 전송은 "커넥터를 지나는 것은 30mm 단거리뿐"이라는 전제로 정당화되었으므로 이 배치는 자기모순입니다. 같은 쪽에 두면 30mm 안에서 끝나고, RS-485 종단도 좌측을 마스터가·우측 끝 모듈이 나머지를 담당하는 정규 토폴로지가 됩니다. C8은 우측 치크블록에 통합, 스피커는 좌·우 엔드캡 유지.

## 9. 오디오와 음원

| 항목 | 사양 |
|---|---|
| 본 음원 | **sfizz (SFZ)** on CM5, Salamander Grand 계열, 128 폴리포니 |
| 폴백 음원 | RP2350 웨이브테이블 32보이스 + 8MB QSPI PSRAM |
| 오디오 버퍼 | period 64 × 3 = **4.00 ms** (이 값 사수가 최우선) |
| DAC | PCM5102A **×2** + NE5532 아날로그 합산 |
| 앰프 | TPA3116D2, 15V, 8Ω, 6W/ch + **LC 출력필터 필수** |
| 스피커 | 3.5" 풀레인지 ×2, 좌우 엔드캡, 러버 그로밋 디커플링 |

**FluidSynth를 기각한 이유**: FluidSynth는 SF2/SF3만 읽고 Salamander Grand는 SFZ 포맷이라 v0.1의 조합은 애초에 성립하지 않습니다. 더 근본적으로 SF2 스펙에는 **릴리즈 트리거가 없어** 건반을 뗄 때의 댐퍼 소음과 페달 기계음을 원리적으로 재현할 수 없습니다. 이것이 "샘플러 소리"와 "피아노 소리"를 가릅니다.

**먹스 대신 듀얼 DAC**: I2S 2:1 먹스로 음원을 전환하려면 "전 보이스 무음 + 제로 크로싱"을 기다려야 하는데, 사용자가 계속 연주하면 그 기회가 오지 않습니다. DAC를 하나 더 달고 아날로그로 합산하면 200ms 크로스페이드가 가능해져 전환 팝이 원천 소멸합니다.

**LC 출력필터는 옵션이 아닙니다.** 1.2m 스피커 배선이 클래스-D 방사 안테나가 되어 매트릭스 센스 라인에 유령 노트를 만듭니다. 필터리스 운용 금지.

> **듀얼 DAC에는 새 문제가 하나 남습니다** — 두 음원의 지연이 다릅니다. 폴백 신스는 약 2.2ms, 도크 sfizz는 5.5~9.5ms입니다. 이 상태로 200ms 크로스페이드를 걸면 같은 노트가 3~7ms 간격으로 두 번 울리는 **플램/콤필터링**이 발생합니다. 도크가 부팅 시 자기 실측 지연 `T_dock`을 스파인에 보고하고, 스파인이 폴백 출력에 `(T_dock − T_local)` 디지털 지연선(128샘플 링버퍼 = 1KB, 부품비 0원)을 삽입해 정렬합니다. **정렬 전에는 크로스페이드를 금지**하고 무음 구간 전환만 허용합니다.
>
> 아날로그 합산기는 NE5532가 아니라 **OPA1662**를 씁니다 — NE5532는 5V 단전원에서 스펙 하한이라 USB 버스전원 모드에서 죽습니다.

| 보조 입력 | USB-C PD 15V/3A → 9V/3A → 5V/3A 폴백 |
| 분배 | **5V 단일 버스** + 모듈별 3.3V LDO |
| 끝단 강하 | **153 mV (3.1%)** — 2oz 8mm 동박, 심당 전원 접점 2병렬 |
| 소비 | 정상 8.0 W / 최대 25.7 W |

> **12V가 아니라 15V인 이유**: USB PD 필수 PDO 경계는 **15W 초과 = 9V, 27W 초과 = 15V, 45W 초과 = 20V**입니다. **12V는 선택 사항이라 설계 기준으로 쓸 수 없습니다.** 20V는 사용자가 만지는 포고핀 전압이 높아지고 eFuse가 고가 부품군으로 밀려나 배제했습니다.
>
> ⚠️ 초기 안은 "45W 이상이어야 15V"로 잘못 인용해 **전압 사다리(15V→9V→5V)** 폴백을 설계했는데, 실제로는 **30W 충전기도 15V/2A를 제공**하므로 이 사다리대로면 멀쩡한 소스에서 스스로 9V로 내려가 앰프 출력을 3dB 잃습니다. 폴백을 사다리가 아니라 **"PDO 목록에서 15V 항목 중 V×I 최대를 선택"**으로 다시 씁니다.

**돌입전류**: 대책이 없으면 모듈 단독 삽입 시 5V ÷ 135mΩ ≈ **37A**가 순간 방전되어 전 모듈이 리셋됩니다. 프리차지 핀(10Ω, τ=1ms) + 소프트스타트로 167mA로 억제합니다.

**접지**: **알루미늄 레일을 시스템의 기계적 기준 접지면으로 채택합니다.** 초기 안은 "모듈은 HF만 본딩, DC 다중접지 금지"였는데, 레일 방식을 채택하는 순간 φ6 강제 다월·M4 무두볼트 3점·M5 손나사가 이미 전 모듈의 DC 접지 경로입니다 — 그 전제는 기구적으로 성립하지 않습니다. 게다가 절연이 막으려던 픽업 루프 기전력은 18µV로 무의미한 반면, **시스템 전체에 ESD 배출 경로가 사라지는** 실질적 손해가 있습니다.

- 레일 ↔ 도크 신호 GND는 도크에서 1점 DC 본딩, 모듈은 레일에 자연스럽게 다중 HF 본딩
- USB-C 실드 셸은 섀시(레일)에 **DC 직결**
- RS-485 A/B · SYNC · 5V 심 접점 전 계통에 **TVS 배치** (현재 전 시스템에 ESD 소자가 사실상 없습니다)
- "스타 그라운드"라는 표현은 폐기 — 400kHz 클래스D와 4Mbps 차동이 공존하는 보드에서 스타 접지는 안티패턴입니다. **앰프 파워루프 봉쇄 + 연속 GND 플레인**으로 대체
- 앰프는 BTL이라 스피커 리턴 전류가 시스템 그라운드를 통과하지 않습니다

**사용자 접촉 활선 접점**: 완전 분할식이라 노출된 레일 패드를 반드시 손으로 만지는데, 그 뒤에 3A급 벅과 분산 벌크 900µF가 상시 연결되어 있습니다. 나사나 드라이버가 5V–GND를 가로지르면 벌크 방전 아크로 금도금 팁이 융착되고 그 접점이 이후 간헐 고장의 진원지가 됩니다. → **PRESENT를 왕복 데이지체인 루프로 만들어 어느 스테이션이든 열리면 도크가 레일 5V를 5µs 내 차단**합니다(배선 1핀 추가, 전압강하 0mV). *레일 미장착 상태에서 패드가 활선이 되지 않는 것*을 제품 안전 요건으로 명기합니다.

## 11. 지연 예산

계약값은 평균이 아니라 **최악**입니다.

| 구간 | 평균 | 최악 | 화음 최악 |
|---|---|---|---|
| 스캔 양자화 (25 kHz) | 20 µs | 40 µs | 40 µs |
| 모듈 상태머신 + vlog LUT | 1.3 µs | 20 µs | 20 µs |
| RS-485 TDMA (10슬롯 × 25µs) | 145 µs | 270 µs | **520~770 µs** |
| 스파인 디코드·라우팅 | 15 µs | 20 µs | 20 µs |
| **하드웨어 소계** | **약 200 µs** | **350 µs** | **600~850 µs** |

> 초기 안의 "최악 260µs"는 **유휴 버스 가정**이었습니다. 화음을 치면 한 모듈에 이벤트가 몰려 슬롯당 2~3개 제한 때문에 MORE 드레인이 걸리고 프레임 1~2개(+250~500µs)가 추가됩니다. 88키 페달 릴리즈 같은 폭주 구간은 1ms를 초과할 수 있습니다.

**(a) USB-MIDI → PC**: 하드웨어 소계 + USB Full-Speed 프레임 대기(평균 500µs / 최악 1000µs) = **평균 0.70 ms / 최악 1.35 ms**. 여기에 호스트 MIDI 스택 + 게임 엔진 입력 폴링 1~3ms가 더해져 게임 애플리케이션 도달은 **2~4ms 예상(미측정)**.

**(b) 온디바이스 — 폴백 신스**: 350 + 블록버퍼 1333 + I2S 21 + DAC group delay 450 + 아날로그 30 = 전기 **2.18 ms** + 공기 전파 2.7ms = **약 4.9 ms** (헤드폰 2.2ms).

**(b) 온디바이스 — 도크 sfizz**: 350 + 링크 30 + **리눅스 UART ingress 300~2000 µs(미측정)** + 콜백 양자화 0~1333 + ALSA `(N+1)×P/fs` = 5333 + I2S 21 + DAC 450 + 아날로그 30 = 전기 6.5~9.5ms + 공기 2.7ms = **9.2~12.2 ms → 목표 10ms 초과 가능**.

> ⚠️ 문서의 "period 64×3 = 4.00ms"는 **링버퍼 깊이이지 note-on → DAC 지연이 아닙니다**. 실제 기여는 (N+1)×P/fs = 5.33ms입니다.
>
> **개선 3종**: ① UART ingress를 SPI + data-ready GPIO로 바꾸고 오디오 콜백 스레드가 직접 드레인 → 추가분 0 ② ALSA를 64×2로 → 1.33ms 절감 ③ 룩어헤드 리미터 금지, 무지연 소프트 클리퍼로 대체. 셋을 적용하면 **총 7.2~8.2ms**로 목표 안에 들어옵니다.

### 3단계로 인계할 계약

1. RP2350은 USB Full-Speed 전용이라 1ms 프레임 양자화를 피할 수 없습니다. 표준 USB-MIDI와 **별도로 (이벤트 + µs 타임스탬프) 사이드채널 엔드포인트**를 병행 열거합니다.
2. **게임 판정은 접점2가 아니라 접점1 시각(t2 − dt) 기준**입니다(§4.3). 접점2 기준이면 세기에 따라 최대 207ms가 흔들립니다.
3. 호스트는 offset뿐 아니라 **skew도 지속 추정**해야 합니다 — 클럭 표류 30~100ppm은 3분 곡에서 5~18ms 누적됩니다.
4. 게임은 피아노 음을 자체 렌더링하지 않습니다. 로컬 5~8ms와 PC 20~40ms가 겹쳐 더블링이 발생합니다. 게임 측에 피아노 음 렌더링 **끄는 스위치를 반드시 제공**할 것.

### 측정 수단을 하드웨어에 박아 넣는다

위 수치는 전부 계산값이고, 현 설계에는 이를 실측할 수단이 없습니다. **T1(모듈 접점2 검출) · T2(스파인 디코드) · T3(오디오 콜백 렌더 시점) 스트로브 3핀 + GND를 외부 헤더로 노출**하고, T1과 라인아웃을 192kHz 오디오 인터페이스 2채널로 동시 캡처(분해능 5.2µs)해 1000타의 평균/p99/최댓값 히스토그램을 냅니다. 이 픽스처(분압 저항 2개 + 헤더 1개)를 BOM에 넣습니다. **계산만으로는 이 항목이 닫히지 않습니다.**

## 15. 확정 필요 (사용자 결정 사항)

1. **도너 키베드 조달** — 중고 스테이지 피아노 해체가 여전히 가장 현실적입니다. 이것이 정해져야 러버 스트립 분할 단위, 접점 저항, 밸런스핀 피치, 백건 폭이 전부 확정됩니다.
2. **연산 도크를 좌·우 어느 쪽 치크에 붙일지** — 자동 열거 방향과 노트 매핑 식이 여기에 종속됩니다.
3. **키 라이팅(88 LED) 채용 여부** — 4단계 리듬게임에서 쓸 계획이면 지금 전력 예산(600mA)에 넣어야 합니다. 나중에 추가하면 전원 재설계입니다.
4. **모듈 라이브 탈착을 공식 지원할지** — 하드웨어 대책은 넣었지만, 지원을 선언하면 동적 재열거·버스 재구성 펌웨어가 추가됩니다.
5. **다운웨이트 목표 (§3.2.1)** — 도너 돔으로 74gf를 받아들일지, 전용 돔 금형 ₩200~350만을 쓸지. **1단계 예산의 최대 단일 변수**입니다.
6. **"도크 없이도 소리가 난다"를 유지할지** — 이건 요구사항이 아니라 설계가 스스로 추가한 목표이고, 대가가 신스 엔진 1벌 + DAC 1개 + 합산기 + 지연 정렬 프로토콜입니다. 포기하면 1단계 범위가 크게 줄고, 유지하더라도 폴백을 "부팅 차임" 수준으로 축소하는 중간안이 있습니다.
7. **페달·전원 버튼·스탠드·케이스 (§13.1)** — 전부 담당자가 없는 상태입니다. 특히 전원 버튼이 없으면 매 세션 리눅스 하드 급단이 반복됩니다.
