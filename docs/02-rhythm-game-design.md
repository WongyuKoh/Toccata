## 0. 이 문서의 위치

> **요약** — Toccata는 **1단계 피아노(하드웨어) → 2단계 리듬게임**으로 가는 프로젝트다. 이 문서는 2단계의 뼈대(개념·구조)를 정하고, 세부 규칙과 숫자는 하드웨어가 확정된 뒤 정한다.

| 순서 | 내용 | 단계 | 이 문서에서 |
|---|---|---|---|
| 1) | 하드웨어 설계·제작 (건반 기구 W1, 옥타브 모듈, 본체, 페달) | **1단계: 피아노** | §2 (게임이 기대는 하드웨어 사실) |
| 2) | 피아노 소리 테스트 (Pi 5 + FluidSynth, 스피커, 지연 10 ms 미만) | **1단계: 피아노** | §6의 건반 점검 화면을 소리 테스트 도구로 함께 쓴다 |
| 3) | 리듬게임 연동 (MIDI 입력, 지연·세기 측정, 보정) | **2단계: 리듬게임** | §2·§10·§11, §12 G1(선택)–G2 |
| 4) | 리듬게임 제작 (판정, 곡·채보, 스토리, 아트) | **2단계: 리듬게임** | §3–§9, §12 G3–G7 |

- **피아노를 만드는 것이 1단계이고, 2단계로 리듬게임을 피아노에 호환되도록 만든다.** 게임은 따로 파는 컨트롤러를 쓰지 않는다. 1단계에서 만든 피아노를 그대로 입력 장치로 쓴다.
- 처음 구상(게임 이름, 내려오는 노트, 흑건 레인, 계속 누르기, 세기 기믹)이 어디에 어떻게 들어갔는지는 §1 끝 "처음 구상 → 반영" 표에 정리했다.
- **세부 내용은 하드웨어 확정 이후에 작업한다.** 이 문서에 나오는 숫자는 대부분 (잠정)이다. 하드웨어가 확정되면 §11 목록에 따라 실측해서 다시 정한다.

## 1. 한눈에 보기

> **요약** — Toccata는 직접 만든 88건반 피아노로 내려오는 노트를 치는 리듬게임이다. 언제 치는지뿐 아니라 **얼마나 세게 치는지, 얼마나 오래 누르고 있는지**까지 판정한다. 현이 끊겨 소리를 잃은 세계를 손끝으로 되살리는 이야기가 이 판정을 감싼다.

| 항목 | 내용 |
|---|---|
| 게임 이름 | **Toccata (토카타)** — 프로젝트 이름과 같다 |
| 이름의 뜻 | 이탈리아어 *toccare*(손대다, 닿다)에서 온 말로, 말뜻은 "손댄 (것)"이다. 르네상스 후기부터 바로크까지 쓰인, 건반을 빠르게 두드려 솜씨를 보이는 건반 곡 형식의 이름이다. 게임 속에서는 손끝으로 세계를 깨우는 사람의 칭호 **"토카타(닿는 자)"** 로도 쓴다 |
| 콘셉트 한 줄 | **현이 끊겨 멈춘 세계를, 진짜 88건반 위의 손끝으로 다시 울리는 피아노 리듬게임** |
| 장르 | 건반 연주형 리듬게임(내려오는 노트 방식) + 이야기 진행(스토리 모드) |
| 플레이 기기 | Toccata 피아노(모듈 1개 이상) + 모니터/TV(HDMI). 댐퍼 페달은 선택이다 |
| 최소 구성 | 옥타브 모듈 **1개(12건반)** 로도 플레이할 수 있다 (6.1·6.3 1옥타브 모드) |
| 인원 | 1인 기본. 2인 협주(한 피아노를 왼쪽·오른쪽으로 나눠 치기)는 확장 목표 |
| 대상 | 피아노를 처음 치는 사람부터 피아노를 배운 사람까지 (난이도 4단) |
| 곡 길이 | 곡당 1분 30초–3분 (시안) |

**핵심 재미 3가지**

| # | 재미 | 무엇이 다른가 |
|---|---|---|
| 1 | **진짜 건반의 손맛** | 버튼이 아니라 실제 피아노에 가깝게 만든 88건반을 친다. 건반 폭 23.5 mm는 실제 피아노와 같고, 누르는 무게 약 52 g·깊이 약 10 mm도 실제 피아노에 맞춰 잡았다(W1 설계값, 제작 후 실측). 게임이 반주만 틀고 선율은 내가 누른 건반의 피아노 소리로 채워진다. 틀린 음도 진짜 소리로 나고, 게임을 할수록 실제 피아노 실력이 는다 |
| 2 | **세기와 홀드를 읽는 판정** | 누르는 순간(타이밍)에 더해 누르는 세기(벨로시티 1–127)와 누르고 있는 시간(홀드)을 판정한다. "세게·여리게·이어서" 치는 **표현**이 점수가 된다. 홀드의 확장으로, 꼬리 끝에서 정확히 놓는 매듭 홀드도 제안한다(놓기 판정 창은 H5 실측 후 정한다) |
| 3 | **건반을 따라 넓어지는 세계** | 세계 지도가 곧 건반이다. 가운데 도(O4)의 도시 **가온도**에서 출발해 서쪽 심해와 동쪽 별로 순례하고, 장이 갈수록 쓰는 음역이 **1옥타브 → 2 → 4 → 88건반**으로 넓어진다. 잘 칠수록 잿빛 도면이던 풍경이 3D 프린터처럼 한 층씩 **다시 인쇄**된다 |

**일반 건반형 리듬게임과 다른 점**

| 구분 | 일반 건반형 리듬게임 | **Toccata** |
|---|---|---|
| 입력 장치 | 버튼 4–8개 | 실제 피아노 건반 88개 + 댐퍼 페달 |
| 레인 | 모두 같은 모양 | 백건 52 + 흑건 36. 흑건은 **위쪽 줄 + 다른 모양 + 경계 위 배치** |
| 입력 정보 | 눌렀다 / 뗐다 | 눌렀다 / 뗐다 + **세기 1–127** + 페달 (떼는 속도·페달 깊이는 하드웨어 확정 후 채택 검토) |
| 소리 | 게임이 효과음을 튼다 | 피아노 음원이 내 연주를 그대로 소리 낸다. 게임은 반주만 튼다 |

**이 게임이 Toccata 피아노에서 잘 돌아가는 이유**

1. **건반마다 홀센서가 따로 있다.** 키보드 매트릭스처럼 여러 키를 누르면 입력이 빠지는 고스팅이 없어서, 화음 노트의 음 수를 센서 때문에 제한할 필요가 없다.
2. **건반 위치를 연속으로 잰다.** 세기(벨로시티)는 건반이 40%→90%를 지나는 시간으로 재고, 빠른 연타는 끝까지 올리지 않아도 다시 치는 재타건으로 받는다. 다만 빠른 반복 구간의 세기 판정은 재타건의 세기 계산 방식을 확인한 뒤(H6) 정한다.
3. **모듈마다 독립된 USB-MIDI 장치다.** 모듈 하나(12건반)만 있어도 게임이 된다. 조립 중인 피아노로도 개발과 시연을 먼저 할 수 있다.

**처음 구상 → 반영**

| 처음 구상 (구상 요지) | 반영한 곳 | 어떻게 반영했나 |
|---|---|---|
| 게임 이름은 프로젝트 이름인 toccata | §1, §7 | 게임 이름 **Toccata**. 세계관에서는 플레이어의 칭호 "토카타(닿는 자)" |
| 피아노 건반으로 하는 리듬게임, 다른 리듬게임처럼 내려오는 노트를 건반으로 누른다 | §3, 4.1 | 88레인 하강 노트. 노트가 판정선에 닿을 때 해당 건반을 누른다 |
| 흰 건반뿐 아니라 검은 건반도 하나의 키로 쓴다 | 3.1 | 흑건 36개도 모두 독립 레인이다 |
| 검은 건반을 **위쪽으로** | 3.1 ① | 흑건 노트는 백건 판정선보다 위에 있는 **흑현(위쪽 판정선)** 에서 판정한다 |

## 2. 1단계 피아노 → 2단계 게임: 어떻게 연결되나

> **요약** — 피아노는 88건반과 페달을 8개의 USB-MIDI 장치로 내보낸다. 게임은 이 MIDI를 **듣기만** 하고 피아노 소리 경로에 끼어들지 않는다. 그래서 게임을 켜도 피아노 소리 지연(10 ms 미만 목표)은 그대로다.

### 2.1 연결 구조

```
[88 keys + damper pedal]
   |  hall sensor per key (DRV5055), ~5,952 reads/s per key
   v
 8 USB-MIDI devices : "Toccata O1" ... "Toccata O7", "Toccata PED"
   |                  (end keys A0-B0 arrive via O1, C8 via O7 -- tentative)
   |
 [USB hub] --(console mode)--> [Raspberry Pi 5 2GB, inside the body]
   |                              |- FluidSynth -> USB audio -> 2 speakers / headphone  (piano, <10 ms)
   |                              |- input bridge -> Toccata game -> micro-HDMI -> TV / monitor
   |                              '- game accompaniment (MIDI) -> the same FluidSynth
   |
   '-----------(PC mode)--------> [PC] Toccata game + FluidSynth (same piano sound)
```

**그림 풀이**: 88건반과 페달의 신호가 USB-MIDI 장치 8개('Toccata O1'–'O7', 'Toccata PED')로 나간다. **콘솔 모드**에서는 본체 안 USB 허브를 거쳐 Pi 5로 들어가고, Pi 5 안에서 음원(FluidSynth)이 피아노 소리를 스피커·헤드폰으로 내는 동시에 입력 브리지가 같은 신호를 게임에 넘긴다. 게임은 화면을 HDMI로 TV·모니터에 내고, 반주를 같은 음원으로 보낸다. **PC 모드**에서는 허브를 PC에 꽂아 PC에서 게임과 음원을 함께 돌린다.

- 피아노는 **옥타브 모듈 7개(O1–O7)** + 왼쪽 끝 부속(A0·A#0·B0) + 오른쪽 끝 부속(C8) + 페달로 이루어진다. 모듈마다 독립된 USB-MIDI 장치라서 **모듈 하나만 꽂아도 12건반 MIDI 키보드**로 동작한다.
- **콘솔 모드**에서는 Pi 5 안에서 FluidSynth와 게임이 같은 MIDI를 **함께 받는다**. 리눅스 ALSA 시퀀서는 MIDI 입력 하나를 여러 프로그램이 동시에 구독할 수 있다. 피아노 소리는 원래 경로 그대로 나고, 게임은 판정·화면·반주만 맡는다.
- **PC 모드**에서는 USB 허브를 PC에 꽂는다. PC에서도 MIDI 장치 8개로 보인다. 이때 Pi는 MIDI를 받지 못하므로, PC에서 FluidSynth와 같은 피아노 음원(Salamander)을 함께 띄워 소리를 낸다.

### 2.2 게임이 쓰는 MIDI 정보

| 피아노가 보내는 것 | 하드웨어 기준 (현재 설계) | 게임에서 쓰는 곳 |
|---|---|---|
| **Note On** + 벨로시티 1–127 | 건반 위치가 **90%** 에 닿는 순간. 세기는 위치 **40%→90% 통과 시간**으로 잰다(빠를수록 셈). 건반별 편차는 보정 모드로 학습한다 | 탭 판정 시각, 세기 기믹 |
| **재타건 Note On** | Note On 뒤 **60% 아래**로 올라왔다가 다시 90%를 넘으면 같은 음을 다시 친다. 끝까지 올리지 않아도 된다 | 연타·트릴. 홀드는 끊지 않는다 |
| **Note Off** (0x80) + 릴리즈 벨로시티 | 위치가 **35% 아래**로 올라올 때. 릴리즈 벨로시티는 0.90→0.40 복귀 속도로 재고 하한은 5다 | 홀드 끝, 매듭 홀드의 놓기, 스타카토, 레가토 |
| **CC64** 0–127 | 댐퍼 페달. 피아노는 0–127 연속값을 보내고, 발을 떼면 정확히 0이다. 다만 **현재 음원(FluidSynth)은 CC64를 64 기준 켜짐/꺼짐으로만 처리**하므로 하프페달 소리는 나지 않는다 | 페달 노트, 전체 쉼 |
| **USB 장치 이름** | 'Toccata O1'–'Toccata O7', 'Toccata PED' | 연결된 모듈 인식, 끊김 감지, 1옥타브 모드, 2인 구분 |
| (보내지 않음) 유령 입력 | 같은 건반에서 음이 난 뒤 **250 ms 안에** 다시 눌림이 오고, 그 내려오는 속도가 **앞 음 속도의 25% 미만**이면 펌웨어가 기계적 튐으로 보고 버린다 | 채보 규칙 R2로 피한다 (9.5) |
| [검토] 누른 깊이 | 펌웨어 안에는 연속 위치값이 있다. 폴리 애프터터치 등으로 게임에 보낼 수 있지만 **아직 구현·확정되지 않았다** | 4.5 압력 홀드 등 |

### 2.5 연결 원칙

1. **게임은 듣기만 한다.** 펌웨어와 음원 설정을 건드리지 않는다. 판정은 MIDI를 받은 시각으로 한다. 게임이 음원에 보내는 것은 반주(피아노와 다른 채널, 10.4)와, 페달이 연결되지 않았을 때의 자동 페달(4.4)뿐이다.
2. **게임이 꺼져도 피아노는 피아노다.** FluidSynth는 게임과 별개 프로그램(시스템 서비스)이라 게임이 멈춰도 소리는 계속 난다.
3. **반주는 게임이, 선율은 당신이.** 노트로 떨어지는 음은 플레이어의 피아노 소리로 난다. 곡이 곧 "연주"가 된다.
4. **모듈 단위로 동작한다.** 모듈이 1개만 연결돼도 게임이 돌고, 연주 중 모듈이 빠지면 어느 모듈인지 알려 준다.
5. **건반만으로 조작한다.** 본체에는 버튼과 화면이 없으므로 메뉴도 건반으로 조작한다(6.4).

## 3. 화면과 레인 구성

> **요약** — 화면 아래에는 실제 배치 그대로의 건반을 그린다. 흰 건반 노트는 **아래 판정선(백현)**, 검은 건반 노트는 그보다 조금 **위쪽의 판정선(흑현)** 에서 친다. 88레인을 한 번에 다 보여 주지 않고, 곡에 맞춰 움직이는 **"음역 창"** 으로 필요한 부분만 크게 보여 준다.

### 3.1 흑건 레인 — 처음 구상의 세 방향

처음 구상은 "단순히 흰색 건반 뿐만 아니라 위쪽으로 혹은 다른 모양/디자인 or 배치로 검은 건반을 하나의 키로 사용"하는 것이었다. **위쪽으로**, **다른 모양/디자인**, **배치** 세 방향을 모두 쓰고, 기본 화면에서는 셋을 겹쳐 쓴다.

| # | 구상 표현 | 이 게임의 방법 | 근거 |
|---|---|---|---|
| ① | **위쪽으로** | 흑건 노트는 백건 판정선(백현)보다 **한 칸 위의 판정선(흑현)** 에서 판정한다 | 실제 피아노를 위에서 보면 흑건은 흰 건반보다 안쪽(먼 쪽)에 있다. 화면에서 먼 쪽은 위쪽이다 |
| ② | **다른 모양/디자인** | 흑건 노트는 폭이 흰 레인의 약 60%인 **좁은 흑요석 육각 결정**이다. 몸통은 어둡고 테두리가 지역 색으로 빛난다. 백건 노트는 레인 폭을 거의 채우는 **넓은 상아색 막대**다 | 색에 기대지 않고 모양·밝기로 구분하므로 색각 이상이 있어도 읽힌다 |
| ③ | **배치** | 흑건 레인은 두 흰 레인의 **경계 위**에 좁게 놓인다(C#은 C와 D 사이). 옵션으로 12칸 균등 배치, 보석 표식형을 둔다(3.3) | 화면 위치 = 손 위치. 실제 건반과 1:1로 대응한다 |

기본안의 이름은 **"이층 현(二層絃)"** 이다. 두 판정선은 세계관 속 "다시 이어진 현"이다(§7).

| (4) | **흑현 (위쪽 판정선)** | 흑건 자리에만 짧게 그은 어두운 줄. 테두리가 지역 강조색으로 빛난다(8.3). 백현보다 화면 높이의 약 6% 위다(0–12% 조절, 시안). 0%로 하면 판정선이 한 줄이 된다 |
| (5) | 흑건 그림 | 흑현과 백현 사이에 흑건 그림이 들어가, 화면 아래쪽이 위에서 내려다본 건반처럼 보인다. 누르면 눌린 모양으로 바뀐다 |
| (6) | **백현 (아래쪽 판정선)** | 화면 전체를 가로지르는 상아색 현. 흰 레인은 흑건 그림 사이 틈을 지나 여기까지 내려온다 |
| (7) | 화면 건반 | 실제 건반과 같은 배치. 누르는 건반이 실시간으로 빛나 "내 손이 어디 있는지" 알려 준다. C마다 음 이름(C4 등)을 적는다 |
| (8) | **울림 게이지** (왼쪽) | 세로로 선 한 가닥의 현. 차오를수록 팽팽해지고 빛난다 |
| (9) | **페달 레인** (오른쪽) | 댐퍼 페달은 오른발로 밟으므로 화면 **오른쪽 끝**에 둔다. 백현과 같은 높이에서 판정한다. 페달이 연결되고 페달 채점을 켰을 때만 보인다 |

- **겹침 처리**: 흑건 레인은 흰 레인 두 개에 절반씩 걸친다. 흑건 레인은 흑현에서 끝나므로 판정 직전(흑현 아래)에는 겹침이 없다. 흑건 노트는 모양(육각 결정 ↔ 막대), 밝기(어두운 몸통 ↔ 밝은 몸통), 판정선 높이(위 ↔ 아래) 세 가지로 동시에 구분한다.
- **화음 연결선**: 같은 순간에 치는 백건·흑건 노트는 판정선 높이가 달라 위아래로 어긋나 보인다. 가는 빛줄로 묶어 "함께 친다"를 알린다.
- 판정선 옆에는 **세기 눈금**을 둔다. 방금 친 벨로시티를 작은 막대로 보여 준다.

### 3.3 다른 방식 (설정에서 고른다)

| 방식 | 배치 | 장점 | 단점 | 쓰는 곳 |
|---|---|---|---|---|
| **A. 이층 현 (기본)** | ①②③을 모두 쓴다 | 실제 건반과 위치가 1:1이라 손이 바로 따라간다 | 레인이 좁아지면 겹침이 늘어난다 | 1–4옥타브 보기 |
| B. 한 줄 모양 구분 | 판정선 하나(흑현 높이 0%). ②·③만 쓴다 | 가장 단순하고 화음을 한 줄로 읽기 쉽다 | 위치 감각이 A보다 약하다 | 입문 옵션 |
| C. 12칸 균등 배치 | 한 옥타브를 12칸 같은 폭으로 나누고 흑건 칸만 어둡게 칠한다 | 겹침이 전혀 없고 흑건 노트가 크다 | 화면 칸과 실제 건반 위치가 조금 어긋난다 | 1옥타브 모드 옵션 "넓은 레인" |
| D. 보석 표식형 | 흑건 노트를 두 흰 레인 경계선 위의 작은 보석으로만 그린다 | 88건반 전체 보기에서 자리를 아낀다 | 작아서 놓치기 쉽다 | 88 파노라마 |

**기본값을 정하는 방법**: 개발 G4에서 A와 B를 각각 5명 이상이 플레이 테스트한다. A의 화음 실수율이 B보다 뚜렷하게 높으면 기본값을 B로 바꾼다 (시안).

### 3.4 88레인을 화면에 담는 방법 — 음역 창

88건반(백건 52 + 흑건 36)을 1920 px 화면에 전부 펴면 흰 레인 하나가 약 37 px로 좁아진다. 그래서 곡의 구간마다 **필요한 음역만 크게** 보여 주는 창을 쓴다.

| 보기 | 보이는 건반 | 흰 레인 수 | 흰 레인 폭 (1920 px 기준, 대략) | 쓰는 곳 |
|---|---|---|---|---|
| 1옥타브 (모듈 보기) | 12 | 7 | 약 270 px | 입문, 모듈 1개만 연결, 서장·1장 |
| 2옥타브 (기본) | 24 | 14 | 약 135 px | 보통 곡 대부분 |
| 4옥타브 | 48 | 28 | 약 68 px | 양손이 넓게 벌어진 곡 |
| 움직이는 창 | 24–60 | 14–35 | 약 55–135 px | 상급. 카메라가 곡을 따라 이동 |
| 88 파노라마 | 88 | 52 | 약 37 px | 달인, 종장, 관람용 (보석 표식형) |

게이지와 페달 칸이 양옆을 차지하므로 실제 폭은 조금 줄어든다(시안). 88 파노라마에서는 게이지와 페달 레인을 레인 위에 반투명으로 겹쳐 그려 레인 폭을 지킨다(시안).

| 규칙 | 내용 |
|---|---|
| 창 이동 예고 | 창이 움직이기 **2박 전(또는 1.5초 전)** 에 화면 가장자리에 화살표와 음 이름(예: "→ C5")을 띄우고, 미니맵에서 다음 창 위치를 깜박인다 (시안) |
| 이동 중 판정 없음 | 창이 움직이는 0.5초 동안에는 판정선에 닿는 노트를 두지 않는다 (시안) |
| 이동 거리 | 보통 난이도 최대 1옥타브, 어려움 이상 최대 2옥타브 (시안) |
| 자동 카메라 | 채보에 창 이벤트가 없으면 "앞으로 4박 안의 노트를 모두 담는 가장 작은 창"을 자동으로 고른다 |
| 두 창 분할 | 왼손 O1, 오른손 O4처럼 멀리 떨어진 구간은 화면을 둘로 나눠 사이 음역을 접는다. 접힌 자리에는 "::" 무늬를 그린다. 비르투오소 난이도와 스토리 6장 이후에서만 쓴다 (R11) |
| 창 밖 노트 | 가장자리에 음 이름이 적힌 작은 화살표로 미리 보여 준다 |
| 옥타브 색띠 | O1–O7마다 레인 바닥에 옅은 고유색(8.2)을 깔아 지금 어느 모듈을 치는지 알린다 |
| 모듈 스티커 (선택) | 실제 건반의 각 C에 화면 색띠와 같은 색 작은 스티커를 붙여 화면과 손 위치를 잇는다. 하드웨어를 바꾸지 않는다 |

### 3.5 화면 크기와 실제 건반 크기

백건 폭은 23.5 mm, 88건반 전체 폭은 약 1,222 mm다(백건 52개 × 23.5 mm).

| 화면 | 가로 폭 (16:9) | 실제 건반과 거의 1:1이 되는 보기 |
|---|---|---|
| 24인치 모니터 | 약 531 mm | 움직이는 창을 3옥타브 폭으로 고정 (백건 21개 ≈ 494 mm) |
| 27인치 모니터 | 약 598 mm | 4옥타브 (백건 28개 ≈ 658 mm, 약 0.91배) |
| **55인치 TV** | **약 1,218 mm** | **88 파노라마 (약 1,222 mm).** 게이지·페달 레인을 레인 위에 겹쳐 그리면 거의 1:1, 양옆에 따로 두면 약 0.9배 |

화면 크기(인치)는 테두리를 뺀 화면 대각선이므로, 위 가로 폭도 테두리를 뺀 실제 화면 폭이다. 피아노 본체(1254 × 410 mm)에는 화면이 없으므로 모니터는 건반 뒤(보면대 자리)나 벽에 둔다. 발표장에서는 **55인치 TV를 피아노 바로 뒤에 두고 88 파노라마를 띄우면 레인과 건반이 거의 1:1로 맞는** 연출이 된다(게이지·페달 레인을 겹쳐 그릴 때). 모니터 위치와 거치 방법은 H17에서 정한다.

### 3.6 판정선과 낙하 시간

- 백현은 화면 아래에서 약 18% 높이에 둔다(시안). 그 아래는 화면 건반이 차지한다.
- 모든 노트는 같은 속도로 내려온다. 흑건 노트는 흑현에 닿는 순간, 백건 노트는 백현에 닿는 순간이 누를 시각이다.
- 낙하 시간(노트가 화면 위에서 판정선까지 오는 시간)은 0.8–3.0초 사이에서 고른다. 기본은 1.5초다(시안). "배속"이 아니라 "초"로 표시해 곡 빠르기와 관계없이 같은 감각을 준다.

## 4. 노트 종류와 기믹

> **요약** — 기본은 **탭**과 **홀드**이고, 여기에 누르는 **세기**를 더한 것이 처음 구상의 중심이다. 그 위에 **화음·연타·트릴**, **댐퍼 페달**, 홀드의 확장인 놓는 **순간**(매듭 홀드)을 더한다. 모든 기믹은 지금 하드웨어가 실제로 보내는 MIDI 정보(Note On/Off, 벨로시티, CC64)만으로 만든다. 새 펌웨어 기능이 필요하거나 확인되지 않은 것은 4.5에 따로 둔다.

### 4.1 기본 노트

| 노트 | 입력 방법 | 화면 표시 | 판정 |
|---|---|---|---|
| **탭** | 한 번 누른다 (Note On) | 백건: 상아 막대 / 흑건: 흑요석 육각 결정 (흑현에서 판정) | Note On 시각을 시간 창으로 판정 (5.1) |
| **화음** | 여러 건반을 동시에 누른다 | 같은 순간의 노트를 가로 빛줄로 묶는다 | 음마다 따로 판정. 퍼짐이 30 ms 이내(잠정)면 "화음" 연출 |
| **아르페지오** | 표시 순서대로 빠르게 차례로 | 계단 모양으로 이어진 노트 | 음마다 따로 판정 |
| **연타** | 같은 건반을 박자에 맞춰 여러 번 | 한 레인에 촘촘히 겹친 노트 + "×N" | 음마다 Note On 시각. 재타건 입력도 한 번으로 센다. 간격은 R1 |
| **트릴** | 이웃한 두 건반을 번갈아 | 두 레인에 걸친 지그재그 띠 | 구간 안 교대 횟수 ÷ 목표 횟수. 100%면 PERFECT, 80% 이상 GREAT, 50% 이상 GOOD (시안). 트릴 하나를 판정 1개로 센다. 속도 상한은 R6 |

- 판정은 **건반 상태**로만 한다. 건반을 90%까지 눌러야 Note On이 나므로, 옆 건반을 살짝 스치는 정도로는 입력이 생기지 않는다.
- 세계관에서 흰 노트는 "상아 막대", 검은 노트는 "흑요 결정"이라 부른다(7.2).

### 4.2 홀드(계속 누르기) 기믹

하드웨어는 건반 위치가 **35% 아래로 올라와야** Note Off를 보낸다. 그래서 끝까지 꽉 누르지 않고 살짝 힘을 빼도 홀드가 유지된다(손 피로 감소). 홀드 도중 건반이 60% 아래로 올라왔다 다시 눌리는 재타건은 같은 음을 다시 치는 것이며, 홀드 판정에서는 끊김으로 보지 않는다. 재타건 전에 Note Off가 먼저 오는지는 H6에서 확인하고, 게임은 두 경우를 모두 처리한다.

| 기믹 (세계관 이름) | 입력 방법 | 화면 표시 | 판정 |
|---|---|---|---|
| **기본 홀드** (현 노트) | 누르고 꼬리 끝까지 유지한다 | 머리 + 빛나는 실(현) 꼬리. 누르는 동안 실이 떨리고, 놓으면 끊어진 실처럼 흩어진다 | 머리 타이밍 + **유지율** (5.3). 꼬리 끝 100 ms 전(시안)부터는 떼도 된다 |
| **매듭 홀드** (매듭 노트) | 누르고, 꼬리 끝 매듭에서 **정확히 놓는다** | 꼬리 끝에 금색 매듭 | 기본 홀드 + **놓기(Note Off) 시각 판정** (5.1 놓기 창) |
| **모으기 홀드** | 누르고 있는 시간만큼 게이지가 차오르고, 표시된 박자(꼬리 끝)에 떼면 발동한다 | 꼬리 옆에 차오르는 원형 게이지 | 머리 + 유지(타이밍 판정 2개). 떼기 시각이 놓기 창 GOOD(5.1) 안이면 발동해 표현 성공(표현 1회) + 배경 연출 (스토리 6장 고래의 물기둥) |
| **닻 홀드** | 한 건반을 쥔 채 다른 손가락·손으로 다른 노트를 친다 | 닻 모양 머리의 긴 현 + 그 위를 지나는 탭들 | 홀드와 다른 노트를 각각 판정. 건반마다 센서가 따로라 동시 입력이 빠지지 않는다 |
| **레가토 사슬** (이음 노트) | 앞 건반을 놓기 **전에** 다음 건반을 누른다 | 노트 사이를 잇는 곡선 빛 다리(악보의 슬러) | 각 머리 판정 + 겹침(앞 Note Off − 뒤 Note On)이 0–80 ms(잠정)면 "이음" 표현 성공 |
| **스타카토** (홀드의 반대) | 짧게 끊어 친다 | 짧은 막대 + 아래 점 `·` | 타이밍 판정 + Note On 뒤 150 ms 안(잠정)에 Note Off면 표현 성공 |
| **쉼표 노트** | 표시된 건반(들)을 그 구간 동안 누르지 않는다. **전체 쉼**이면 모든 건반과 페달에서 손발을 뗀다 | 레인을 덮는 회보라 안개 + 쉼표 기호. 전체 쉼은 화면 가로 전체 안개 띠 | 구간 동안 새 Note On 0개면 성공. 전체 쉼은 여기에 모든 건반 Note Off + CC64 = 0까지 요구한다. 콤보는 끊지 않는다 |

- **홀드의 확장.** 매듭 홀드와 쉼표 노트는 스토리의 주제(7.6) "닿으면 울리고, 놓아야 이어진다"를 연주로 느끼게 하는 확장 기믹이다. 스토리에서는 7장에서 처음 배우고 종장에서 모인다. 곡 선택 모드에서는 비르투오소에서 나온다(9.4).
- 판정은 **건반 상태**로 한다. 페달을 밟아 소리가 이어져도 건반을 뗐으면 홀드는 끝난 것으로 본다.
- 재타건 때 펌웨어가 Note Off를 먼저 보내는 경우(H6)에는, 바로 뒤에 오는 같은 건반 Note On까지를 홀드 재접속(5.3)으로 처리해 홀드를 끊지 않는다.

### 4.3 세기(벨로시티) 기믹

벨로시티는 1–127이고, 하드웨어는 건반이 40%→90%를 지나는 시간으로 잰다. 게임은 이 값을 **세기 구간**으로 나눠 판정한다.

**기본 3단 (프렐류드 Lv3 이상 모든 난이도, MVP 포함)** — 목표로 쓰는 것은 p와 f 두 가지다. mf는 "요구 없음" 구간이다.

| 구간 | 기호 | 벨로시티 (잠정) | 노트 표시 |
|---|---|---|---|
| 여리게 | *p* | 1–50 | 얇은 테두리, 반투명 하늘색, 작은 빛무리 |
| 보통 | *mf* | 51–90 | 보통 테두리. 목표로 요구하지 않는다 |
| 세게 | *f* | 91–127 | 두 겹 두꺼운 테두리, 주홍색, 무거운 그림자 |

**확장 5단 (벨로시티 곡선 실측 H3 이후, 달인 난이도)**: *pp* 1–30 · *p* 31–55 · *mf* 56–80 · *f* 81–105 · *ff* 106–127 (모두 잠정). 벨로시티 곡선을 재기 전에는 5단을 쓰지 않는다.

**개인 세기 보정**: 스토리 서장에서 홀의 안내로(또는 설정 화면에서) "가장 여리게 8번, 가장 세게 8번"을 친다. 여린 쪽과 센 쪽 값으로 플레이어의 실제 범위를 잡고 구간 경계를 그 범위에 맞춰 늘리거나 줄인다. 원래 구간 대비 최대 ±20까지만 옮긴다(잠정). 절차는 10.5 보정 표에 있다.

| 기믹 (세계관 이름) | 요구 | 벨로시티 조건 (잠정) | 화면 표시 | 성공 / 실패 |
|---|---|---|---|---|
| **강약 노트** | 지정 세기(*p* / *f*)로 친다 | 위 구간 | 노트 옆에 악보식 기울임 기호 *p* / *f* + 테두리 두께 | 구간 안이면 표현 성공 |
| **깨기 노트** (굳은 돌) | 세게 쳐야 깨진다 | 91 이상 | 금 간 돌 질감 | 성공하면 돌이 깨진다. 약하면 "튕김"으로 돌이 남는다. 같은 건반의 다음 노트는 300 ms 이상 뒤에 둔다 (R2 ④) |
| **유리 노트** | 살며시 쳐야 산다 | 50 이하 | 투명 유리, 반짝임 | 성공하면 유리가 맑게 울린다. 세면 "깨짐"으로 금이 간다. 늦은 쪽 판정 창 +15 ms (5.1) |
| **크레셴도 사슬** | 3–8개 음을 점점 세게 | 단계의 70% 이상에서 앞 음보다 +4 이상, 첫 음과 끝 음 차이 30 이상 | 점점 커지는 노트 + "<" 쐐기 띠 | 사슬 전체를 한 번 판정. 단계 비율에 비례해 부분 점수 |
| **디크레셴도 사슬** | 점점 여리게 | 크레셴도의 반대 | 점점 작아지는 노트 + ">" | 같음 |
| **메아리 노트** | 같은 음형을 세게 한 번, 여리게 한 번 | 앞 *f* → 뒤 *p* | 두 번째 노트는 반투명 | 같은 건반이면 두 노트 간격 **300 ms 이상** (R2) |
| **강조 화음** (보이싱) | 화음 중 빛나는 한 음만 더 세게 | 강조음 ≥ 나머지 평균 +12 | 화음 속 한 노트에 작은 왕관 | 선율을 살리는 실제 피아노 기술. 어려움 이상 |
| **여림 구간** | 구간 안 모든 노트를 여리게 | 구간 안 어느 음도 60 초과 금지 | 레인에 푸른 안개 + 잠든 생물 그림 | 60을 넘으면 "깨움"으로 표현 실패. 끝까지 조용하면 성공 |
| **세기 파동** (연출) | — | — | 모든 타격에서 현이 떨리는 크기 = 벨로시티. *f*는 짧은 충격파, *p*는 작은 빛방울 | 점수와 무관. "내 세기"를 눈으로 보여 준다 |

- **한 번의 실수에 두 번 벌을 주지 않는다.** 세기를 틀려도 타이밍 판정은 그대로이고 콤보도 이어진다. 표현 점수만 잃고 게이지가 1단위 줄어든다(5.1·5.4).
- **사슬과 같은 건반 반복**: 크레셴도·디크레셴도 사슬 모두, 같은 건반이 300 ms 안에 이어지는 단계는 사슬 판정에서 뺀다(R2·R3). 채보 변환기가 헤어핀을 사슬로 바꿀 때 이런 단계를 자동으로 뺀다(9.6). 반복음이 많은 크레셴도(예: 「산왕의 궁전에서」)는 서로 다른 건반으로 넘어가는 음만 사슬 단계로 쓴다.
- 크레셴도 사슬, 강조 화음처럼 **앞 음이나 옆 음과 비교하는 상대 판정**은 절대값 판정보다 사람마다 다른 세기 감각에 덜 민감하다. 다만 서로 다른 건반을 이어 치는 경우가 많아 건반별 세기 편차가 그대로 들어간다. 그래서 **펌웨어의 건반별 보정이 전제**다(H3).
- 연타·트릴처럼 같은 건반을 빠르게 반복하면 재타건으로 칠 가능성이 높다. 재타건 벨로시티를 어떻게 계산하는지 확인하기 전(H6)에는 이런 구간에 세기 판정을 붙이지 않는다(R3).

### 4.4 페달 활용

페달은 **선택**이다. 'Toccata PED'가 연결돼 있고 설정에서 "페달 채점"을 켰을 때만 페달 노트를 판정한다. 페달 **소리**를 누가 맡는지는 채점과 관계없이 PED 연결 여부로만 정한다.

| 상황 | 페달 소리를 맡는 것 |
|---|---|
| PED 연결됨 (채점을 켜든 끄든) | **실제 페달.** PED의 CC64가 ALSA 시퀀서로 FluidSynth에 바로 들어간다. 게임은 CC64를 보내지 않는다 |
| PED 없음 | **자동 페달.** 게임이 채보의 페달 기록대로 CC64를 **피아노와 같은 채널**(H1 가정: 채널 1)로 FluidSynth에 보낸다. 플레이어가 친 선율에도 페달이 걸리므로 추가 비용 없이 곡 소리가 온전하게 유지된다 |
| 연주 중 PED가 빠짐 | 게임이 CC64 = 0을 한 번 보내 걸려 있던 페달을 풀고, 곡의 현재 위치부터 자동 페달로 넘어간다. 그 곡의 페달 채점은 끈다 |
| 연주 중 PED가 다시 연결됨 | 자동 페달을 멈추고(CC64 = 0) 실제 페달에 넘긴다 |

| 페달 노트 | 입력 | 화면 표시 (오른쪽 페달 레인) | 판정 (잠정) |
|---|---|---|---|
| **밟기** | 표시된 박자에 페달을 밟는다 | 망토 자락 모양 막대의 시작 | CC64가 64 이상이 된 시각 |
| **유지** | 밟은 채 유지한다 | 긴 망토 자락 막대 | 구간 동안 CC64 ≥ 64 유지율 |
| **떼기** | 표시된 박자에 발을 뗀다 | 막대 끝 꺾쇠 | CC64가 64 미만이 된 시각. 현재 음원에서 소리가 끊기는 순간과 같다 (64 부근 떨림 거름은 H10) |
| **바꿔 밟기** | 화음이 바뀔 때 페달을 뗐다가 곧바로 다시 밟는다 | 막대 사이 V자 홈 | 뗌→밟음이 150 ms 안이면 성공 (H10에서 확인). 뗌과 밟음을 합쳐 페달 노트 1개로 센다 (R10 예외) |
| 하프페달 [검토] | 구간 동안 반만 밟는다 | 점선 막대 + 목표 깊이 | CC64 30–90 유지. 현재 음원(FluidSynth)은 64 기준 켜짐/꺼짐이라 하프페달 소리가 나지 않는다. 하프페달을 지원하는 음원으로 바꾸고 정밀도를 H10에서 확인한 뒤 쓴다 |

| 난이도 | 페달의 역할 |
|---|---|
| 입문·보통 | 판정 없음, 페달 레인 숨김. 소리는 위 규칙을 따른다 (PED가 있으면 실제 페달, 없으면 자동 페달) |
| 어려움 | 페달 레인 켜기 선택 |
| 달인 | 페달 레인 기본 켜짐 |

- 페달 노트가 없는 곡에서는 페달을 밟아도 감점하지 않는다. 페달은 음악적으로도 쓰는 장치다.
- 스토리에서 댐퍼 페달은 **"소리 망토"** 다. 소리를 붙잡아 두는 힘이라, 적(페르마타)의 힘과 같은 뿌리를 가진다(§7).

## 5. 판정·점수·게이지

> **요약** — 타이밍은 PERFECT·GREAT·GOOD·MISS 4단계로 판정한다. 세기·이음·쉼 같은 연주 표현은 따로 **표현 점수**로 매긴다. 만점은 1,000,000점이고, 게이지는 스토리에서 **세계의 색이 돌아오는 높이**로 보인다.

### 5.1 타이밍 판정

| 판정 | 세계관 이름 | 누르기 창 (잠정) | 놓기 창 (잠정) | 점수 비율 | 콤보 | 게이지 (시안, 기준 단위) |
|---|---|---|---|---|---|---|
| **PERFECT** | 공명 | ±35 ms | ±50 ms | 100% | 이어짐 | +1.0 |
| **GREAT** | 맑음 | ±70 ms | ±100 ms | 70% | 이어짐 | +0.6 |
| **GOOD** | 스침 | ±110 ms | ±150 ms | 30% | 이어짐 | +0.2 |
| **MISS** | 잿빛 | 창 밖 / 안 침 | 창 밖 / 일찍 뗌 | 0% | 끊김 | −4.0 |

- **판정 시각** = 입력 브리지가 기록한 MIDI 수신 시각 − **입력 보정값**(10.5). **어긋남** = 판정 시각 − 노트의 예정 시각(곡 시계, 10.4). 입력 보정값 하나에 오디오 출력 지연(8–10 ms)과 손 습관이 함께 들어 있으므로 곡 시계에는 출력 지연을 따로 더하지 않는다. 화면 프레임 시각은 쓰지 않는다.
- **창 크기의 근거**: 입력 경로(센서 → USB → 브리지)의 흔들림 목표는 ±2 ms 이하(잠정)로, PERFECT 창의 10분의 1보다 작다. 화면·반주 지연은 고정값이라 보정으로 없앤다(10.5). 흔들림이 크게 나오면 창을 넓힌다(H4).
- **여린 노트 보정**: 여리게 치면 40%→90% 통과가 느려 Note On이 늦게 온다. *p* 목표 노트와 유리 노트는 **늦은 쪽 창만 +15 ms** 넓힌다(잠정).
- 입문(프렐류드) 난이도는 모든 창을 1.2배로 넓힌다(시안).
- 판정마다 FAST/SLOW를 작게 띄우고, 연습 모드에서는 ms 숫자까지 보여 준다.
- **게이지 열의 값은 기준 단위다**(시안). 곡마다 1단위를 몇 %로 바꿀지 노트 수에 맞춰 정한다(5.6). 세기 실패(5.4)와 정확 모드의 불협(5.2)도 같은 단위로 −1.0이다.

### 5.2 입력과 노트 연결

| 규칙 | 내용 |
|---|---|
| 인식 창 | 노트 시각 ±150 ms(잠정) 안의 누름만 그 노트에 연결한다 |
| 연결 순서 | 같은 건반에 노트가 여러 개면 **가장 이른 미판정 노트**에 연결한다. 입력 하나 = 노트 하나 |
| 불협 (빈 타건) | 어느 노트에도 연결되지 않은 누름. 기본은 점수·콤보에 영향이 없고 소리만 난다. 실제 피아노에서는 옆 건반을 스치는 일이 흔하기 때문이다. 불협 수는 기록해 CLEAN 배지에 쓴다. "정확 모드"를 켜면 게이지 −1.0단위 (5.1) |
| 재타건 | 누른 상태에서 또 Note On이 오면 "다시 침"으로 보고, 탭·연타 노트에는 새 입력으로 준다. 홀드는 끊지 않는다 |
| 모듈 끊김 | 연주 중 모듈이 빠지면 곡을 일시정지하고 "O3 연결 끊김"을 띄운다. 그 모듈에서 눌려 있던 건반은 **모두 뗀 것**으로 처리한다(걸린 홀드 방지) |

### 5.3 홀드 판정

| 판정 요소 | 방법 |
|---|---|
| 머리 | 탭과 같다 (Note On 시각) |
| 유지율 | 누른 시간 ÷ 요구 시간 (꼬리 끝 100 ms 전까지). **95% 이상 PERFECT, 80% 이상 GREAT, 50% 이상 GOOD**, 그 아래는 MISS (시안) |
| 놓기 (매듭 홀드만) | Note Off 시각을 놓기 창(5.1)으로 판정한다. 모으기 홀드의 떼기는 타이밍 판정이 아니라 표현 판정 1회다(4.2) |
| 재접속 | 홀드 중 실수로 뗐을 때 **150 ms 안(잠정)** 에 다시 누르면 이어진다. 뗀 시간만 유지율에서 빠진다. 다시 누를 때는 **mf 이상(잠정)** 으로 눌러야 한다. 여리게 다시 누르면 유령 거름에 걸릴 수 있기 때문이다(거름의 기준 시점은 H7에서 확인) |

- **타이밍 판정 개수** (5.5 타이밍 점수의 분모): 탭·화음·아르페지오·연타는 음마다 1, 기본 홀드·닻 홀드·모으기 홀드는 2(머리 + 유지), 매듭 홀드는 3(머리 + 유지 + 놓기), 트릴은 1(교대율), 레가토 사슬·스타카토는 음마다 1(이음·끊음은 표현), 쉼표 노트와 페달 노트는 0(표현만). 긴 홀드가 점수를 독차지하지 않게 하려는 것이다.

### 5.4 세기 판정

| 결과 | 조건 | 효과 |
|---|---|---|
| **성공** | 벨로시티가 목표 구간 안 | 표현 점수 100% |
| **근접** | 구간 경계에서 8 이내로 벗어남 (잠정) | 표현 점수 50% |
| **실패** | 그 밖 | 표현 점수 0%, 게이지 −1.0단위(5.1). 타이밍 판정과 콤보는 그대로 |

크레셴도·디크레셴도 사슬, 강조 화음, 여림 구간은 4.3의 조건을 따른다.

### 5.5 점수

| 항목 | 배점 | 계산 |
|---|---|---|
| 타이밍 점수 | 900,000 | 900,000 × (모든 타이밍 판정의 점수 비율 합 ÷ 판정 개수). 홀드는 유지율 판정, 매듭 홀드는 놓기 판정까지 포함한다 |
| 표현 점수 | 100,000 | 100,000 × (표현 점수 비율 합 ÷ 표현 기회 수). 표현 점수 비율은 성공 1, 근접 0.5(5.4), 실패 0이고, 사슬은 단계 비율에 따른 부분 점수(4.3)다. 표현 기회 = 세기 기믹, 레가토 사슬, 스타카토, 모으기 홀드, 쉼표 노트, 페달 노트(채점 켰을 때) |

비율은 시안이다. 표현 비중 10%는 "타이밍만 잘 쳐도 곡은 깰 수 있고(타이밍 만점이면 900,000점, A), S(950,000) 이상은 표현 점수를 절반 이상 얻어야 받게" 하려는 값이다. 세기 기믹이 표현 기회의 절반을 넘는 곡에서는 세기를 무시하고 S를 받기 어렵다.

### 6.3 연결된 모듈에 맞춰 바뀌는 게임

모듈마다 독립 USB-MIDI 장치이므로, 게임은 시작할 때 **어떤 모듈이 연결됐는지** 장치 이름으로 알 수 있다. 끝 부속은 O1·O7 장치에 딸려 들어오므로(2.3) 따로 감지하지 않는다. 미니맵은 O1·O7이 연결되면 끝 부속 구역도 함께 켠다.

| 상황 | 게임의 처리 |
|---|---|
| 88건반 모두 연결 | 모든 곡·모드 |
| 모듈 일부만 연결 | 곡 목록에 "필요 모듈" 아이콘을 띄운다. 없는 모듈의 노트는 ① 연결된 옥타브로 접거나 ② 게임이 자동 연주한다 (플레이어가 고름) |
| 모듈 1개만 연결 | 1옥타브 모드로 자동 전환 |
| 페달 없음 | 자동 페달 (4.4) |
| 연주 중 모듈이 빠짐 | 일시정지 + "O3 연결 끊김" 안내. 그 모듈의 눌린 건반은 모두 뗀 것으로 처리 (5.2) |

**1옥타브 접기 규칙**: 음 번호를 12로 나눈 나머지(음이름)로 모든 노트를 한 옥타브에 모은다. 겹친 노트는 하나로 합친다. **접은 채보도 R1–R16 전체 검사를 다시 통과해야 한다.** 여러 옥타브를 한 옥타브로 모으면 같은 건반 최소 간격(R1), 같은 건반 센 음 뒤 여린 음(R2), 강타 반복(R9), 한 옥타브 안의 C·C#·D 동시 누름(R13) 같은 위반이 새로 생길 수 있다. 위반 노트는 빼거나 세기 요구를 지운다. 이 작업은 채보 검사기가 자동으로 한다(9.6). 접으면 음악이 어색해질 수 있으므로, 스토리 서장·1장처럼 처음부터 한 옥타브로 편곡한 곡을 따로 둔다.

**그림 풀이**: 타이틀에서 네 갈래로 간다. **스토리**는 세계 지도 → 장 선택 → 두루마리 컷씬 → 곡 → 결과 → 지도로 돌아온다. **곡 선택**(현탑 도서관)은 곡 목록 → 난이도·보기 → 곡 → 결과다. **연습**은 곡 목록 → 구간·속도 → 곡(반복)이다. **설정**에서는 지연 보정, 세기 보정, 건반 점검, 화면 프로필을 고른다.

## 7. 스토리와 세계관

> **요약** — 현(絃)이 모두 끊겨 소리를 잃은 대륙 **현누리**. 플레이어는 손끝만으로 소리를 깨우는 "토카타"가 되어, 가운데 도의 도시 **가온도**에서 출발해 서쪽 심해와 동쪽 별로 건반을 따라 순례한다. 목표는 세계를 한 화음 속에 가둔 끝나지 않는 늘임표 **"페르마타"** 를 풀어내는 것이다. 주제는 **"닿으면 울리고, 놓아야 이어진다."**

### 7.1 여는 말 (게임 첫 화면 내레이션)

> 옛날, 현누리에는 현이 있었다.
> 바람이 현을 스치면, 세계가 노래했다.
>
> 어느 날, 마지막 화음이 끝나지 않았다.
> 너무 오래 울린 소리는 현을 하나씩 끊었고, 세계는 잿빛 도면처럼 멈췄다.
>
> 이제 현은 없다.
> 남은 것은 88개의 탑, 그리고 당신의 손끝.

### 7.2 세계: 현누리 — "지도가 곧 건반인 대륙"

- **현누리**는 "현(絃)의 누리(세상)"라는 뜻으로 지은 이름이다. 대륙은 서쪽 끝 깊은 바다 밑에서 동쪽 끝 하늘까지 **길게 한 줄로 뻗어 있고**, 그 위에 **현탑(絃塔) 88개**가 늘어서 있다. 52개는 상아로 된 **상아탑**, 36개는 흑요석으로 된 **흑요탑**이다. 흑요탑은 상아탑들보다 한 단 높은 안쪽 둔덕에 서 있다. 흑건 노트가 위쪽 판정선(흑현)에서 판정되는 이유다.
- 노트는 탑에서 떨어져 내리는 빛 조각이다. 상아탑에서는 **상아 막대**(흰 노트), 흑요탑에서는 **흑요 결정**(검은 노트)이 내려온다.
- 대륙 한가운데에는 가운데 도의 도시 **가온도**가 있다. 서쪽(낮은 음)으로 갈수록 땅이 깊어져 숲·광맥·바다 밑이 되고, 동쪽(높은 음)으로 갈수록 높아져 고원·구름·별에 닿는다. **음이 높아질수록 세계도 높아진다.**
- 탑과 탑 사이에는 원래 현이 걸려 있었고, 바람이 현을 스치면 세계 전체가 하나의 악기처럼 울렸다. 이 시대를 **"현의 시대"** 라 부른다.
- 탑을 깨우는 기술을 **토카레**(손끝으로 닿기)라 하고, 이를 할 줄 아는 사람을 **토카타(닿는 자)** 라 불렀다.
- 대륙 땅속에는 **자철 광맥**이 동서로 길게 흐른다. 광맥의 한 줄기는 가온도 시계탑 밑을 지나고, 본맥은 서쪽 땅속 깊이 뻗어 있다.

### 7.5 장 구성 — 88의 순례

순례는 **가온도(O4)에서 출발해 서쪽과 동쪽으로 번갈아 퍼져 나간다.** 장이 갈수록 쓰는 음역이 1옥타브 → 2옥타브 → 4옥타브 → 88건반으로 넓어지고, 종장에서 처음으로 88건반 전체와 양 끝 부속을 쓴다. 발표 때 실제로 있을 하드웨어가 모듈 1개여도 이야기 앞부분(서장·1장)을 시연할 수 있다.

**장의 옥타브 원칙**: 각 장은 한 지역(옥타브 모듈)을 "주 무대"로 삼지만, **선율은 가운데 음역(O3–O5)에 둔다.** 주 무대 옥타브가 가운데에서 먼 장(4·5·6·7장, 종장)은 그 옥타브를 테마·특수 노트(저음 홀드, 깨기 노트, 종소리 트릴, 유리 노트)에만 쓴다(R15). 극저음은 소리가 뭉개지고, 서브우퍼 없는 4인치 스피커 2개로는 잘 들리지 않으며, 연주자가 본체 끝으로 몸을 빼야 하기 때문이다.

- **해금 규칙**: 장의 각성곡을 클리어하면 다음 장이 열린다. 곡마다 음표 인장 3개(클리어 / A 이상 / FULL COMBO)를 모은다.
- **스토리 채보의 난이도 규칙**: 스토리 곡은 곡 선택 모드의 난이도 4단(9.4)과 따로, 장마다 한 벌의 스토리 채보로 친다. 노트 밀도·같은 건반 최소 간격(R1)·판정 창은 서장·1장은 프렐류드, 2–4장은 에튀드, 5장–종장은 소나타 기준을 따른다. 기믹은 **그 장까지 배운 것만** 쓰고, 그 장에서 새로 배우는 기믹은 9.4의 등장 난이도와 관계없이 쉬운 형태로 넣는다(예: 5장의 트릴은 느린 트릴, 6장의 두 창 분할은 짧은 구간). 보기는 위 표를 따르고, 게이지는 보통 게이지이며 보호 게이지(5.6)를 고를 수 있다.
- **덤**: 순례 순서가 "가운데 모듈부터 하나씩 더해 가는 피아노 조립 순서"와 같다. 모듈을 하나 완성할 때마다 해당 장의 곡을 시험해 볼 수 있다.

### 7.6 결말과 주제

1. **7장 — 굳은 화음**: 페르마타는 싸우지 않는다. 대신 노트 일부를 잿빛 돌로 굳히고(깨기 노트), 곡의 흐름을 붙잡아 늦춘다(리테누토: 곡의 빠르기가 점점 느려진다. 노트는 같은 속도로 떨어지므로 노트 사이가 벌어지고, 배경의 시계 바늘이 멈칫거린다). 그녀는 말한다. "끝나면 사라져. 그래서 멈춘 거야."
2. **종장 — 88의 토카타**: 88건반 전체를 쓰는 마지막 곡이다. 양 끝의 세 초석과 마지막 별이 처음으로 깨어난다. 곡의 끝에서 수백 년 전의 **그 화음**이 거대한 홀드 노트로 내려오고, 플레이어는 소리 망토(페달)까지 밟아 소리를 붙잡는다. 배경에는 거대한 늘임표 기호 하나만 떠 있다.
3. **놓기**: 매듭이 판정선에 닿는 순간, **모든 건반과 페달을 함께 놓아야** 한다(모든 건반 Note Off + CC64 = 0, 놓기 판정). 성공하면 세계에 수백 년 만의 **진짜 쉼표**(완전한 침묵 2초, 전체 쉼 노트)가 온다.
4. **마지막 별**: 침묵 뒤에 C8 하나가 홀로 내려온다. **아주 여리게**(유리 노트) 한 번 닿으면, 끊겼던 현들이 동쪽 끝에서 서쪽 끝까지 다시 이어진다.
5. **그 뒤**: 리테나는 사라지지 않고 "현탑 도서관"의 사서가 되어 끝난 곡들을 모아 둔다. 끝난 곡만이 다시 연주될 수 있기 때문이다. 엔딩 뒤 자유 연주와 채보 공방이 열린다.

> **주제: "닿으면 울리고, 놓아야 이어진다."**
> 소리는 끝나야 다음 소리가 온다. 이것은 **이야기의 주제**다. 판정 설계의 중심은 처음 구상대로 홀드와 세기이고, 매듭 홀드·스타카토·쉼표 노트는 이 주제를 연주로 느끼게 하는 확장 기믹이다.

### 7.7 이야기를 전하는 방법

| 규칙 | 내용 |
|---|---|
| 곡 사이에만 이야기 | 곡 도중에는 글자를 띄우지 않는다. 배경 변화로만 이야기한다 |
| 짧게 | 곡 사이 컷씬은 정지 그림 1–3점 + 대사 2–4줄이다. 음성은 없다. 학생 제작 규모에 맞춘다 |
| 악보 두루마리 | 컷씬은 "악보 두루마리"가 펼쳐지는 형식이다. 대사 옆에 셈여림 기호를 붙여 말투를 나타낸다 (*p* 속삭임, *f* 외침) |

### 7.8 세계관 ↔ 실제 Toccata 하드웨어 대응표 (발표용)

게임 세계는 **이 피아노를 닮게** 만들었다. 발표에서 1단계(피아노)와 2단계(게임)가 하나의 이야기로 이어지는 근거가 된다.

| 게임 세계 | 실제 Toccata 피아노 |
|---|---|
| 현이 끊긴 세계, "현 없이 닿음만으로 울린다" | **현이 없는 디지털 피아노**. 건반 위치를 센서로 읽어 소리를 합성한다 |
| 길잡이 정령 **홀**, "얼마나 깊이·빨리 닿았는지 느낀다" | 건반마다 달린 **홀센서 DRV5055**. 위치를 연속으로 재고 40→90% 통과 시간으로 세기를 잰다 |
| 홀이 태어난 **자철 광맥** | 건반 밑의 **자석** |
| 무게추 파수꾼 **레바**, "무게가 있어야 되돌아온다" | 캡스턴이 들어 올리는 **강철 무게 레버(53.7 g)**. 무게와 작은 비틀림 스프링으로 건반이 돌아온다 |
| 파수꾼 **레바**가 가르치는 빠른 연타 (4장) | 펌웨어 **재타건**. 60% 아래로 올라왔다가 다시 90%를 넘으면 다시 친다 |
| 7개 지방 (1–7장) | **옥타브 모듈 O1–O7** |
| 가온도에서 출발해 양 끝으로 퍼지는 순례 | **모듈 하나(O4)로도 동작하고, 모듈을 더해 88건반이 되는 피아노** |
| 세 초석 / 마지막 별 (종장) | **왼쪽 끝 부속 A0·A#0·B0 / 오른쪽 끝 부속 C8** (O1·O7 모듈에 딸려 들어온다) |
| 소리 망토 | **댐퍼 페달** (CC64 0–127 연속값을 보낸다. 현재 음원에서는 64 기준 켜짐/꺼짐) |
| 잿빛 도면이 층층이 인쇄되며 되살아나는 풍경 | **3D 프린팅**. 도면에서 시작해 한 층씩 쌓아 만든 피아노 |
| 흑요탑이 한 단 높은 안쪽에 선다 | 실제 흑건이 흰 건반보다 안쪽(높은 곳)에 있다 → 흑현이 위쪽 |

## 8. 배경·아트 스타일

> **요약** — 아트 스타일의 이름은 **「도면에서 적층으로」** 다. 소리를 잃은 세계는 잿빛 종이 위의 가는 선(도면)이고, 플레이어가 잘 칠수록 풍경이 3D 프린터처럼 **아래에서 위로 한 층씩 색이 쌓여** 되살아난다. 노트와 판정선은 상아·흑요석·빛나는 현으로 통일한다.

### 8.1 세 가지 상태

| 상태 | 언제 | 모습 |
|---|---|---|
| **도면** | 곡 시작 전, 게이지가 낮을 때 | 잿빛 종이 질감 위에 가는 흑연 선만 있다. 치수선·중심선 같은 보조선이 희미하게 보인다. 색이 없다 |
| **적층** | 연주 중, 게이지가 오를수록 | 풍경이 바닥부터 가는 가로 층(적층선)으로 한 층씩 색이 채워진다. 게이지 40% → 화면 40% 높이까지 색이 찬다. 층 사이 가는 선이 보인다 |
| **완성** | 곡이 끝나고 클리어 | 적층선이 부드럽게 녹아 빛나는 색면이 되고, 탑 꼭대기에서 현이 다시 이어진다. 실패하면 층이 다시 도면으로 흐려진다 |

- 이 방식은 **평평한 2D 색 층을 쌓는 그림**이라 그리기 쉽고, Raspberry Pi 5에서도 부담이 적다. 무거운 3D나 실시간 조명이 없다.
- **88개 현탑 수평선**: 배경 먼 곳에 작은 탑 88개가 건반 순서대로 늘어서 있다. 건반을 누르면 그 건반의 탑에 불이 켜진다. 스프라이트 88개라 가볍다.

### 8.2 지역별 색

음이 낮은 지역일수록 어둡고 무겁게, 높은 지역일수록 밝고 가볍게 칠한다. **음높이가 곧 명도**다(6장 O1 → 4장 O2 → 2장 O3 → 3장 O5 → 5장 O6 순으로 바탕이 밝아진다). 다만 **밤·땅속 장면**(서장 광맥, 1장 밤 축제, 7장 오로라 밤하늘, 종장 별하늘)은 예외로 바탕을 어둡게 두고, 강조색의 밝기로 높이를 나타낸다. 강조색은 흑건 노트 테두리, 판정 빛, 레인 바닥 옥타브 색띠(투명도 10–15%)에 쓴다. **옥타브 색띠는 모듈마다 한 색**이다. O4 색띠는 1장 색(`#F2B544`)을 쓰고, 서장 색은 서장 연출에만 쓴다.

|---|---|---|---|
| 서장 | 시계탑 밑 광맥 (O4) | `#07080C` 칠흑 | `#FFE7A8` 홀의 빛 |
| 1장 | 가온도 (O4) | `#2E2442` 보랏빛 밤 | `#F2B544` 등불 금색 |

### 8.6 가독성·접근성

- 흑건/백건은 **모양·밝기·판정선 높이**로 구분하고 색에 기대지 않는다. 모든 기믹은 색 + 모양 + 기호 세 가지로 구분한다.
- 배경 움직임 끄기, 화면 흔들림 끄기, 강한 번쩍임 줄이기, 고대비 모드(배경 완전 검정, 노트 흰색/노란 테두리)를 둔다.
- 노트가 떨어지는 구역 안에는 배경 애니메이션을 두지 않는다.

## 9. 음악과 채보 규칙

> **요약** — 곡은 **직접 만든 오리지널**과 **저작권 보호기간이 끝난 클래식·전래 민요를 직접 편곡**한 것만 쓴다. 채보는 건반 기구의 연타 한계와 펌웨어의 "유령 거름"을 지키도록 규칙을 정하고, 채보 검사기가 자동으로 확인한다.

### 9.1 곡을 마련하는 원칙

| 구분 | 쓸 수 있나 | 방법 |
|---|---|---|
| 오리지널 곡 | O | 직접 작곡하거나 무료 작곡 도구로 만든다. 장마다 주제 선율을 하나씩 둔다 |

### 9.3 반주와 선율

- 게임은 **반주만** 튼다. 선율(플레이어 파트)은 플레이어가 친 피아노 소리로 채워진다. 입문·연습에서는 "가이드 음"(6.2)을 켤 수 있다.
- 반주는 같은 악보에서 반주 파트만 **MIDI**로 내보내고, 게임이 이 MIDI를 **피아노와 같은 FluidSynth**에 다른 채널로 보내 재생한다(10.4). 녹음 음원이 없으니 저작권 문제가 생기지 않고, 속도 조절(50–100%)을 해도 음정이 변하지 않으며, 음원 파일 용량도 없다.
- 반주 음색은 기본적으로 같은 피아노 음원(Salamander)을 쓴다. 현악·타악 반주가 필요한 곡만 무료 GM 사운드폰트를 추가한다(메모리 10.6).

### 9.4 난이도

난이도 이름은 곡의 형식에서 따왔다.

| 난이도 | 레벨 | 보기 | 노트·기믹 | 세기 | 한 손 동시 건반 | 같은 건반 최소 간격 (R1) | 판정 창 |
|---|---|---|---|---|---|---|---|
| **프렐류드** (입문) | 1–3 | 1옥타브 | 탭, 기본 홀드, 한 손 | 없음 (Lv3부터 *p*/*f*) | 2 | 250 ms | ×1.2 |
| **에튀드** (보통) | 4–7 | 2옥타브 | + 화음, 레가토, 스타카토, 연타 | 3단 (*p*/*f*) | 3 | 167 ms | ×1.0 |
| **소나타** (어려움) | 8–11 | 2–4옥타브 | + 양손, 아르페지오, 닻 홀드, 사슬, 강조 화음, 페달(선택) | 3단 + 사슬 | 4 | 125 ms | ×1.0 |
| **비르투오소** (달인) | 12–15 | 4옥타브–88 | + 트릴, 두 창 분할, 매듭 홀드, 쉼표 노트, 페달 | 3단 → 5단 (H3 이후) | 5 | 100 ms | ×1.0 |

한 손 동시 건반 수, 레벨 계산, 판정 창 배율(×1.2)은 시안이고, 같은 건반 최소 간격과 판정 창 크기(5.1)는 잠정이다. 표의 노트·기믹 등장 난이도는 **곡 선택 모드** 기준이다. 스토리 모드에서는 7.5의 "스토리 채보의 난이도 규칙"에 따라 그 기믹을 배우는 장부터 나온다. **레벨 계산 (시안)**: 밀도(초당 노트 수) + 도약(음역 창 이동, 손 이동 거리) + 표현 요구(세기·홀드 기믹 수)를 더한 뒤 플레이 테스트로 손본다.

### 9.5 하드웨어를 반영한 채보 규칙

| # | 규칙 | 값 | 이유 (하드웨어) |
|---|---|---|---|
| R1 | 같은 건반 연속 노트 최소 간격 | 입문 250 ms, 보통 167 ms, 어려움 125 ms, 달인 100 ms (잠정) | 연타 한계는 백건 약 16 Hz(62.5 ms), 흑건 약 19 Hz다. 달인도 한계의 약 60%(10 Hz)까지만 쓴다 |
| R2 | **유령 거름 피하기** | ① 같은 건반에서 **300 ms 안에 이어지는 노트에는 세기 요구를 붙이지 않는다.** ② 같은 건반 앞 노트 뒤 300 ms 안에 *p*(5단에서는 *pp* 포함) 목표 노트를 두지 않는다. ③ 메아리 노트는 같은 건반이면 300 ms 이상 띄운다. ④ 앞 노트에 ***f*·깨기·강조음·크레셴도 끝음** 요구가 있으면, 같은 건반의 다음 노트는 **세기 요구가 없어도** 300 ms 이상 띄운다. ⑤ 연타·트릴 구간 안과 그 직전 300 ms 안에는 그 구간의 건반에 세기 목표 노트를 두지 않는다. **간격은 앞 노트의 머리(Note On)부터 재고, 앞 노트가 홀드면 꼬리 끝부터 잰다**(H7 전까지 보수적으로) (모두 잠정) | 펌웨어는 같은 건반에서 음이 난 뒤 250 ms 안에 다시 눌림이 오고, 그 속도가 앞 음 속도의 25% 미만이면 버린다. 버려지면 세기만 틀리는 것이 아니라 Note On이 사라져 타이밍 MISS가 나고 콤보도 끊긴다. 250 ms에 여유를 두어 300 ms로 적었다. ④는 센 음 바로 뒤에 플레이어가 자연스럽게 여리게 친 음이 버려지는 것을 막는다. "한 구간만 낮추기" 같은 규칙은 *p* → *pp*(예: 50 → 10, 속도 20%)를 막지 못한다. 최종 조건은 벨로시티↔속도 곡선을 잰 뒤 "앞 음 대비 벨로시티 비율"로 정한다 (H7). 검사기가 ①–⑤를 모두 확인한다 |
| R3 | 빠른 반복에는 세기 판정 없음 | 연타·트릴·(검토 중인) 롤·되울림 구간 | 재타건 벨로시티 계산 방식 미확인 (H6) + R2와 같은 이유 |
| R4 | 홀드 끝 → 같은 건반 다음 노트 | 120 ms 이상 (잠정) | 35%까지 올라와야 Note Off가 나고 다시 90%까지 눌러야 한다. 끝까지 복귀 약 45 ms + 사람의 여유. 유령 창이 앞 음의 Note On부터라면(현재 사양) 홀드가 300 ms 이상(R5)이라 거름에 걸리지 않는다. H7에서 기준이 Note Off로 확인되면 300 ms로 올린다 |
| R5 | 홀드 최소 길이 | 300 ms 이상 (시안) | 탭과 헷갈리지 않게 |
| R6 | 트릴 속도 | 두 건반 합쳐 초당 16회 이하 (건반 하나당 8회) (잠정) | R1과 같은 이유 |
| R7 | 한 손 화음 폭 | 입문 5도 이내, 그 밖 1옥타브 이내, 달인 10도 이내 (시안) | 건반 폭 23.5 mm = 실제 피아노와 같아서 사람 손 기준이 그대로 적용된다 |
| R8 | 양손 동시 건반 | 8개 이하 (시안) | 센서는 제한이 없다(건반별 독립). 사람 손 기준 |
| R9 | **강타 반복 제한 (내구)** | 같은 건반 *f* 이상 목표 노트는 연속 4개까지, 강타 사이 300 ms 이상 (R2 ④와 같은 값) (잠정) | 3D 프린팅 건반과 무게 레버에 반복 충격이 몰리지 않게 (내구 시험 H13 전) |
| R10 | 페달 노트 간격 | 400 ms 이상 (잠정). 바꿔 밟기(뗌→밟음)는 페달 노트 1개로 보고 그 안의 간격은 재지 않는다 | 페달 기구 반응 미측정 (H10) |
| R11 | 음역 창 이동 | 2박(또는 1.5초) 전 예고, 이동 중 0.5초 판정 없음, 두 창 분할은 비르투오소와 스토리 6장 이후에서만 (시안) | 88건반을 한 번에 크게 보여 줄 수 없다 |
| R12 | 모듈 경계를 넘는 화음 | 허용. 판정은 음마다 따로 하므로 영향이 없다. 화음 연출 기준 30 ms(잠정)는 4.1과 같은 값이다 | 30 ms는 사람 손의 화음 퍼짐에 맞춘 연출용 값이다. 모듈 사이 USB 도착 차이는 1–2 ms 수준(10.5)인지 H11에서 확인한다 |
| R13 | **조작 조합 금지** | 한 옥타브 안의 C·C#·D 동시 누름(일시정지)을 채보에 쓰지 않는다 | 메뉴 조작과 겹치지 않게 (6.4) |
| R14 | 검토 중 기믹 금지 | 글리산도·되울림·롤은 하드웨어 확정 전 채보에 쓰지 않는다 | 4.5, H6·H12·H13 |
| R15 | 장의 옥타브 원칙 | 선율은 O3–O5에 두고, O1·O2·O6·O7과 끝 부속은 특수 노트·저음 홀드·반주 보강에만 쓴다 (시안) | 극저음은 소리가 뭉개지고 4인치 스피커로 잘 들리지 않으며, 연주 자세도 나빠진다 |
| R16 | 스토리 서장·1장 | O4 한 모듈 안에서 끝나게 채보 | 모듈 1개로 시연할 수 있게 |

### 9.6 채보 만드는 과정

```
1) arrange in MuseScore (free): RH/LH staves, dynamics, accents (>), hairpins (< >), staccato, pedal marks
2) export MusicXML
3) chart converter (Python + music21): notation -> game notes
     long note / tie -> hold        accent -> strike (f) note
     p region marks  -> soft note   hairpin -> cresc / decresc chain
     pedal mark      -> pedal note  staff   -> hand (for practice mode)
4) rule checker: R1-R16 -> list of bars that break a rule (R15 = warning only)
     + auto-generate the 1-octave folded chart (6.3) -> run R1-R16 again on it
5) accompaniment part -> MIDI track played live through FluidSynth (no audio render)
6) auto-play bot (all PERFECT?) -> human playtest -> tune difficulty
```

**그림 풀이**: ① 무료 악보 프로그램 MuseScore로 편곡하고 셈여림·악센트(>)·헤어핀(< >)·스타카토·페달 표시를 적는다. ② MusicXML 파일로 내보낸다. ③ 채보 변환기(Python + music21)가 악보 기호를 게임 노트로 바꾼다. 긴 음·붙임줄은 홀드, 악센트는 강타(*f*) 노트, *p* 구역은 여린 노트, 헤어핀은 크레셴도·디크레셴도 사슬, 페달 표시는 페달 노트, 오선(오른손·왼손)은 손 구분이 된다. ④ 규칙 검사기가 R1–R16을 어긴 마디를 찾고(R15는 경고만), 1옥타브로 접은 채보를 만든 뒤 그것도 다시 검사한다. ⑤ 반주 파트는 MIDI 트랙으로 두고 FluidSynth로 바로 연주한다(오디오 파일을 만들지 않는다). ⑥ 자동 연주 봇으로 모두 PERFECT가 나는지 확인하고, 사람 플레이 테스트로 난이도를 맞춘다.

- 자유 연주 모드에서 녹음한 MIDI도 3)에 넣어 **Toccata로 직접 친 연주를 채보 초안**으로 쓸 수 있다.
- **변환기가 자동으로 만든 세기 노트도 검사를 통과해야 한다.** 악센트 → *f*, 헤어핀 → 사슬로 바뀐 노트는 R2·R3·R9를 다시 확인한다. 반복음 속 악센트(예: 「산왕의 궁전에서」, 「라 캄파넬라」)처럼 규칙을 어기는 세기 요구는 변환기가 지우고 보통 탭으로 남긴다. 같은 건반이 300 ms 안에 이어지는 사슬 단계는 사슬에서 뺀다(4.3).
- 채보 파일은 사람이 읽을 수 있는 **JSON**이다. 시각(`t`)과 길이(`len`, `gap`)는 박 단위로 적어 템포가 바뀌어도 깨지지 않게 한다.
- `pedal`은 채보의 페달 기록이다. 페달 채점을 켜면 페달 노트로 판정하고, PED가 없으면 자동 페달로 보낸다(4.4).

**채보 파일 예시 1** (1장 「흑건」 쉬운 편곡의 앞부분, 곡 선택 모드 프렐류드 Lv3, 1옥타브 보기)

```json
{
  "meta":    { "title": "Black Key Etude (easy arr.)", "composer": "F. Chopin", "arranger": "Toccata",
               "tempo": [[0, 96]], "tier": "PRELUDE", "level": 3, "modules": ["O4"] },

    { "t": 1.0, "key": 66, "type": "tap" },
```

흑건만 쓰고, 탭 3개(F#4·G#4·F#4), 기본 홀드 1개(A#4), *p*/*f* 강약 노트 1개씩(D#4·C#4)만 넣었다. 프렐류드 Lv3 규칙(9.4)과 같은 건반 간격 규칙(R1·R2)에 맞는다.

## 10. 기술 구성

> **요약** — 콘솔(Pi 5) 기준 게임은 **Python + pygame(SDL2 KMSDRM: 데스크톱 없이 화면에 바로 그리는 방식)** 으로 만든다. 저장소 하드웨어 설계의 결정(OS Lite + SDL KMSDRM)과 같다. MIDI 입력은 게임과 떨어진 작은 **입력 브리지**가 도착 순간의 시각과 함께 받는다. 반주는 MIDI로 피아노와 같은 FluidSynth에 보낸다. 화면·소리 지연은 보정 화면으로 없앤다.

### 10.1 전체 구성

```
[8 USB-MIDI devices: Toccata O1..O7, PED]
        |  Linux ALSA sequencer: several programs subscribe to the same port
        +--> FluidSynth (system service): piano sound -> ALSA hw: (USB audio) -> speakers
        +--> input bridge (Python: mido + python-rtmidi)
               - connect by device name, handle plug / unplug
               - timestamp each message on arrival (monotonic clock, us), receive thread
               - (device, note) -> key index 0..87
               - record / replay / fake input from PC keyboard
                    |  localhost UDP : {time, key, type, velocity}
                    v
             Toccata game (pygame)
               - song clock = scheduled sequencer time (output latency is inside the input offset)
               - judge: (input time - input offset) - note time -> timing result
               - renderer: lanes, notes, effects, range window, minimap
               - accompaniment player: MIDI -> the same FluidSynth (other channels)
```

**그림 풀이**: 8개 USB-MIDI 장치의 신호를 리눅스 **ALSA 시퀀서**(MIDI 신호를 여러 프로그램에 나눠 주는 기능)가 두 곳에 보낸다. ① **FluidSynth**(시스템 서비스)는 피아노 소리를 USB 오디오로 스피커에 낸다. ② **입력 브리지**(Python: mido + python-rtmidi)는 장치 이름으로 연결하고 꽂고 빼기를 처리하며, 메시지가 도착한 순간의 시각(μs)을 기록하고 (장치, 음 번호)를 건반 번호 0–87로 바꾼다. 기록·재생과 PC 키보드 가짜 입력도 맡는다. 브리지는 같은 컴퓨터 안 **UDP**(짧은 메시지를 빠르게 보내는 방식)로 {시각, 건반, 종류, 세기}를 게임에 넘긴다. 게임은 곡 시계(반주를 예약한 시각)와 입력 시각을 비교해 판정하고, 레인·노트·효과·음역 창·미니맵을 그리며, 반주를 같은 FluidSynth의 다른 채널로 보낸다.

[하드웨어 설계서 §7.1](01-hardware-design.md#71-os-lite와-pygame) 결정과 같다(옛 v2.0 §6.1, [보관본](archive/v2.0-monolithic.md#61-os-lite--sdl-kmsdrm)) | 입력 브리지가 시각을 기록한다 | 2D 층 그림·스프라이트에 충분하다. UI는 직접 그려야 한다 | **기본안.** 콘솔 모드와 PC 모드를 같은 코드로 |
| Godot 4 | 리눅스에서 X11/Wayland 표시 서버가 필요하다. OS Lite에서는 키오스크용 Wayland 컴포지터(예: cage) 위에서 돌려야 한다. 이때 컴포지터나 오디오 스택이 오디오 장치(ALSA hw:)를 잡지 않는지 확인해야 한다 | 기본 MIDI 입력은 프레임 단위로 처리되고 모듈(장치)을 구분하는지도 불확실하다 → 입력 브리지로 보완 | 편집기·애니메이션이 강하다 | [검토]. G2에서 조건(오디오 장치 비선점, 60 fps)을 통과하면 G3 전에 전환할 수 있다 (H15) |
| 웹 (Chromium + Web MIDI) | 브라우저를 띄울 표시 서버가 필요하고 메모리가 크다 | 이벤트에 도착 시각이 붙는다 | 좋다 | PC 시연·공유용 후보 |
| Unity | Pi 5(ARM 리눅스)에서 돌리기 어렵다 | 플러그인 필요 | — | 제외 |

**입력 브리지를 엔진과 떼어 둔 이유**: 판정에는 "화면 프레임 시각"이 아니라 "신호가 도착한 시각"이 필요하다. 60 fps의 한 프레임은 약 17 ms로 PERFECT 창 ±35 ms에 비해 너무 크다. 브리지는 엔진과 무관하므로 나중에 엔진을 바꿔도 그대로 쓴다.

### 10.3 MIDI 입력 처리 (입력 브리지)

| 단계 | 하는 일 | 세부 |
|---|---|---|
| ① 장치 찾기 | 'Toccata O1'–'O7', 'Toccata PED'를 이름으로 자동 연결 | 2초마다 다시 찾는다. 없는 모듈은 미니맵에 회색으로 표시 |
| ② 시각 기록 | 메시지가 도착한 순간을 μs 단위로 기록 | 운영체제 단조 시계(CLOCK_MONOTONIC), 수신 스레드에서. 게임 프레임과 무관 |
| ③ 건반 번호 정리 | (장치, 음 번호) → 건반 번호 0–87 (A0 = 0, 가온 도 C4 = 39, C8 = 87) | 절대 음 번호(21–108)면 그대로, 모듈마다 같은 번호면 장치별 옥타브를 더한다 (H1). 끝 부속은 O1·O7 장치로 들어온다 (H2) |
| ④ 신호 해석 | Note On(세기 > 0) = 누름, Note Off(0x80) 또는 세기 0 = 뗌, CC64 = 페달 | 릴리즈 벨로시티도 저장한다(쓸지는 H5) |
| ⑤ 재타건 처리 | 누른 상태에서 또 Note On → "다시 침" | 재타건 전에 Note Off가 먼저 오는 경우도 처리한다 (H6) |
| ⑥ 게임에 전달 | localhost UDP로 {시각, 건반, 종류, 세기} | 입력-노트 연결은 게임의 판정기가 5.2 규칙으로 한다 |
| ⑦ 이상 감시 | 모듈 끊김을 게임에 알린다 | 게임은 일시정지하고 그 모듈의 눌린 건반을 모두 뗀 것으로 처리 (5.2) |

**시계 맞추기**: 게임은 시작할 때와 30초마다 브리지와 핑-퐁을 주고받아 두 시계의 차이를 잰다. 같은 컴퓨터 안이라 오차는 0.1 ms 안팎으로 예상한다(잠정).

### 10.4 반주·오디오 경로

[하드웨어 설계서 §7.1](01-hardware-design.md#71-os-lite와-pygame)의 결정을 따른다(옛 v2.0 §6.1, [보관본](archive/v2.0-monolithic.md#61-os-lite--sdl-kmsdrm)). OS는 Raspberry Pi OS Lite이고, FluidSynth는 ALSA `hw:`로 출력 장치(현재 설계는 USB 오디오 동글)를 **배타적으로** 쓴다. 게임 소리는 믹서를 두지 않고 **반주를 MIDI로 FluidSynth에 보내 같은 신스로 재생**한다.

| 소리 | 경로 | 비고 |
|---|---|---|
| 피아노 (플레이어 연주) | 모듈 → ALSA 시퀀서 → FluidSynth → USB 오디오 → 헤드폰 잭 / 앰프 → 스피커 | 게임이 끼어들지 않는다. 키→소리 10 ms 미만 목표 (예상 8–10 ms) |
| 반주 | 게임 → ALSA 시퀀서 출력 포트 → 같은 FluidSynth, 피아노와 다른 채널 | 믹서 없음, 같은 클록. 오디오 장치 선점 문제가 없다 |
| 메뉴·효과음 | 반주와 같은 경로 (MIDI 음) | 곡 중 판정음은 기본으로 끈다. 피아노 소리가 곧 피드백이다 |
| 대안 | 반주를 HDMI 오디오(TV 스피커)로 따로 낸다 | 반주와 피아노 소리의 지연이 달라진다. 그 차이만큼 반주를 앞당겨 보내고 입력 보정을 다시 한다 |

- **곡 시계** = 반주 이벤트를 예약한 시퀀서 시각. 출력 지연은 곡 시계에 더하지 않는다. 플레이어는 반주와 자기 피아노 소리를 같은 출력 경로로 들으므로, 남는 차이는 입력 보정값 하나가 흡수한다(5.1, 10.5). 반주가 기준이라 소리와 판정이 어긋나지 않는다.
- **연습 속도 50–100%**: 시퀀서 템포만 바꾸므로 음정이 변하지 않는다. 오디오 파일을 렌더하지 않는다.
- **반주 음색**: 기본은 피아노 음원(Salamander)을 그대로 쓴다(추가 메모리 0). 다른 악기가 필요한 곡만 GM 사운드폰트(예: FluidR3_GM, 약 141 MB)를 추가한다(잠정).
- **측정 항목 (H14)**: 반주가 나는 동안에도 피아노 키→소리 지연이 10 ms 미만으로 유지되는지, FluidSynth 동시 발음 수와 CPU가 모자라지 않는지 잰다.
- **PC 모드**: PC에서 FluidSynth와 같은 피아노 음원을 함께 띄운다. Windows는 저지연 출력 설정이 필요할 수 있다.

### 10.5 지연 예산과 보정

| 구간 | 크기 (잠정) | 판정에 주는 영향 |
|---|---|---|
| 건반 위치 측정 (건반마다 초당 약 5,952번) | 0.2 ms 이하 | 거의 없다 |
| 펌웨어 판단 (90% 도달 → Note On) | 거의 0 | 세기는 40→90% 구간에서 이미 계산돼 있다 |
| USB-MIDI 전달 + 장치 8개 병합 + 브리지 시각 기록 | 1–2 ms | 흔들림(지터: 지연이 매번 조금씩 달라지는 것)의 원인 |
| 피아노 소리 (FluidSynth → USB 오디오 → 스피커) | 10 ms 미만 목표 (예상 8–10 ms) | 플레이어가 자기 소리를 듣고 맞추는 데 포함된다 → 입력 보정으로 흡수 |
| 화면 표시 | 모니터 10–30 ms, TV 20–100 ms (기기마다 다름) | 고정값 → 화면 보정으로 없앤다. TV는 "게임 모드" 권장 |

**고정 지연은 보정하면 사라지지만 흔들림은 사라지지 않는다.** 흔들림 목표를 ±2 ms 이하(잠정)로 두고 G2에서 먼저 잰다. 5.1 판정 창의 근거다. 건반은 90% 깊이에서 Note On이 나므로 손이 느끼는 "바닥에 닿음"과 조금 차이가 있다. 이 차이도 입력 보정이 함께 흡수한다.

**보정 절차 (첫 실행. 1·2번은 서장 전에 약 1분, 3번은 서장 안에서)**

| # | 보정 | 방법 | 결과 |
|---|---|---|---|
| 1 | **입력 보정** | 메트로놈 소리(반주와 같은 FluidSynth 경로)에 맞춰 아무 건반이나 16번 친다. 가장 어긋난 2개를 빼고 "수신 시각 − 예정 시각"의 평균을 낸다 | **입력 보정값** (ms). 판정 시각 = 수신 시각 − 입력 보정값 (5.1). 오디오 출력 지연과 손 습관이 함께 들어 있다 |
| 2 | **화면 보정** | 소리 없이 판정선에 떨어지는 빛 막대에 맞춰 16번 친다 | 노트를 그리는 위치를 앞당기는 값 (ms) |
| 3 | **세기 보정** | 스토리 서장에서 홀의 안내로(또는 설정 화면에서) 가장 여리게 **8번**, 가장 세게 **8번** 친다 | 플레이어별 세기 구간 (4.3) |
| 4 | 자동 제안 | 곡이 끝날 때 평균 어긋남이 ±15 ms(시안)를 넘으면 입력 보정값 조정을 제안한다 | — |

- 화면 장치마다 **화면 프로필**을 따로 저장한다("거실 TV", "교실 모니터").
- **지연 실측**: 스마트폰 240 fps 슬로모션으로 건반·화면·소리를 함께 찍는다. 1프레임이 약 4.2 ms라 지연을 눈으로 셀 수 있다.

| H10 | 페달 CC64 기준값·하프페달 정밀도·반응 속도 | 밟음 64 이상, 뗌 64 미만(현재 음원 FluidSynth가 64 기준 켜짐/꺼짐이라 소리와 판정을 맞춘다), 64 부근 떨림 거름 없음, 하프 30–90(하프페달 지원 음원일 때만), 페달 노트 간격 400 ms, 바꿔 밟기 150 ms | CC64 곡선·반응 속도 측정, 바꿔 밟기 시험 | 4.4, R10 |

| H12 | 글리산도 가능 여부 | 채보에 넣지 않음 | 쓸기 동작의 90% 도달률, 건반 모서리·손 안전 | 4.5, R14 |
| H13 | **내구·소음**: 강타 반복, 롤, 연타 소음 | 강타 연속 4개·300 ms 간격 제한, 롤 보류 | 내구 시험에 강타 반복과 롤을 포함 | 4.5, R9 |

| H19 | 유령으로 거른 입력을 게임에 알릴지 (연습·디버그용) | 알리지 않는다 | 펌웨어 확정 | 5.2, 연습 모드 |

## 12. 개발 계획

> **요약** — 게임은 프로젝트 순서 **3) 연동 → 4) 제작**에 해당하고, **1단계 피아노가 확정된 뒤** 본격적으로 만든다. 지금(G0)은 기획서·세계관·아트 시안만 만든다. 하드웨어 일정이 밀릴 때만 시판 MIDI 키보드로 입력 시제품(G1, 선택)을 먼저 만들 수 있다. 하드웨어가 확정되면(H) 연동과 측정으로 숫자를 정하고, 모듈 1개로 도는 핵심 루프 → 88레인·채보 도구 → 콘텐츠 → Pi 이식 순으로 만든다.

### 12.1 마일스톤

H = 하드웨어 확정 시점(모듈 1개 이상이 최종 펌웨어로 동작). 기간은 1인, 주 8–10시간 기준의 잠정값이다(도움을 받으면 줄어든다).

| 단계 | 시기 (잠정) | 할 일 | 결과물 | 완료 기준 |
|---|---|---|---|---|
| **G0 기획** | 지금 (1단계와 함께) | 이 기획서, 세계관, 아트 시안, 곡 후보, 종이로 레인 배치 시험 | 기획서 v1, 콘셉트 그림 3점 (도면 / 적층 / 완성), 화면 목업 | 발표 |
| G1 입력 시제품 (선택) | H 이전, 하드웨어 일정이 밀릴 때만 | 입력 브리지 + 12레인 탭·홀드 판정 + 리플레이 (시판 MIDI 키보드·가짜 입력) | 시제품 | 1곡을 끝까지 칠 수 있다 |
| **G2 연동** (= 순서 3) | H – H+2주 | 'Toccata O1–O7·PED' 인식, 건반 점검 화면, Note On/Off·재타건·CC64 로그, 지연·흔들림·세기 분포 측정, **R1 최소 간격 연타 100회 무누락 시험**(H7), 엔진·표시 서버 확정 | 측정표, §11 H1–H11·H15 값 | 흔들림 기록(목표 ±2 ms 이하), 판정 창 확정 |
| **G3 핵심 루프** | H+2 – H+5주 | 1옥타브 모드: 탭·홀드·흑현, 판정·점수·게이지, 보정 3종, 세기 3단(*p*/*f*) | 플레이 가능한 1옥타브 곡 3개 | 친구 3명이 보정 후 PERFECT 비율 50% 이상 |
| **G4 88레인·채보 도구** | H+5 – H+8주 | 음역 창·미니맵, 흑건 배치 A/B 테스트, 채보 변환기 + 검사기(R1–R16), 1옥타브 접기 | 4옥타브 곡 플레이, 곡 1개를 1시간 안에 채보 | 흑건 배치 기본값 결정 |
| **G5 콘텐츠 1차·아트** | H+8 – H+12주 | 서장 + 1장(곡 3–4개), 도면 → 적층 → 완성 연출, 컷씬, 결과 화면(실수 지도·세기 그래프) | 데모 빌드 | 처음 하는 사람이 서장을 도움 없이 클리어 |
| **G6 콘솔 이식** | H+10 – H+13주 | Pi 5에서 게임 + FluidSynth, 반주 MIDI 경로, 메모리·프레임 맞추기, 자동 시작 | 콘솔 모드 | 1080p(또는 720p) 60 fps, 반주 중 키→소리 10 ms 미만 유지 |
| **G7 다듬기·시연** | H+13 – H+15주 | 플레이 테스트(5명 이상), 난이도 조정, 시연 영상 | 시연 빌드 | 시연 3회 연속 문제 없음 |
| G8 확장 | 이후 | 2–7장·종장, 세기 5단, 2인 협주, 자유 연주, 채보 공방, [검토] 기믹 | 정식판 | — |

G1(선택)–G2가 프로젝트 순서 **3) 리듬게임 연동**, G3–G7이 **4) 리듬게임 제작**에 해당한다. 기본 순서는 **1단계 피아노 → 2단계 게임(G2부터)** 이고, G1은 하드웨어 일정이 밀릴 때 쓸 수 있는 선택안이다. 합계는 H 이후 약 15주(잠정)이고 하드웨어 일정에 맞춰 조정한다.

### 12.2 전체 구상과 발표 범위

| 구분 | 전체 구상 | 발표 MVP (첫 플레이 가능 목표) |
|---|---|---|
| 스토리 | 서장 + 1–7장 + 종장 (9개 장 × 곡 2–3개) | **서장 + 1장 1곡** |
| 곡 | 클래식 10곡 이상 + 자작곡 | 3–4곡 (「첫 닿음」, 「아리랑」, 「흑건」 쉬운 편곡) |
| 하드웨어 | 88건반 + 페달 | **모듈 1개 (O4 권장)** |
| 노트 | §4의 노트 전부 | 탭, 기본 홀드, 흑건 위쪽 줄, 강약 노트 (*p*/*f*) |
| 세기 | 3단 → 5단(H3 이후) | 3단 (*p*/*f* 목표만) |
| 화면 | 1·2·4옥타브, 움직이는 창, 88 파노라마 | 1옥타브 보기 |
| 시스템 | 전체 | 점수·게이지·결과 화면, 도면 → 적층 연출, 지연 보정, 세기 보정, 건반 점검 |
| 빼는 것 | — | 두 창 분할, 페달 레인, 트릴, 2인 협주, 채보 공방, [검토] 기믹 |

- 기본 홀드와 강약 노트는 스토리에서는 2·3장에서 배우는 기믹이다. MVP 스토리(서장 + 1장)에는 넣지 않고, **곡 선택 모드**의 같은 곡 채보(프렐류드 Lv3, 9.6 예시 1)로 보여 준다.
- **지금 발표(G0)** 에서 보여 줄 것은 이 기획서, 세계관 대응표(7.8), 아트 시안(도면 → 적층 → 완성), 화면 목업(3.2, 5.8)이다.
- **세부 규칙과 수치는 하드웨어 확정 뒤 작업한다.** 발표 자료 첫 장 또는 게임 기획 요약 장에 이 한 줄을 넣는다. 마지막 쪽은 부품 목록 전용이다.
